# DataMark 视频标注工作台

Ubuntu 内网部署是现行主服务，本机模式用于开发和旧数据处理。平台支持多账号视频标注，React + TypeScript + Vite 前端与 FastAPI 后端由同一服务提供；本机地址为 **http://127.0.0.1:8765**。Ubuntu 内网入口使用 HTTPS，不开放到公网。

本文件是当前安装、使用、数据格式与维护说明。人工 GT 按事实核对，目录分类和采集计划不会自动成为标签；时间轴空白表示未标注，不表示行为没有发生。IMU 对齐、采集总览和模型评估尚未实现。

## 浏览器登录凭据

登录页先获取两分钟有效的一次性凭据，再使用浏览器标准加密接口对账号和密码加密，通过 `/api/auth/login-encrypted` 提交；网络请求面板只显示随机密文。加密使用 RSA-OAEP/SHA-256 包装随机 AES-256-GCM 密钥，凭据编号参与校验，服务端校验有效期、来源客户端及单次使用，篡改或重放均拒绝。公钥与私钥由当前服务进程管理，私钥仅在内存中保留；服务重启后，旧登录凭据失效，重新点击登录即可。当前部署使用单进程；扩展到多进程、多副本前须共享凭据状态或保证请求进入同一实例。

密码框不把密码绑定到 HTML 的 `value` 属性或 React 状态；读取并开始加密后立即清空输入框，准备或登录失败也清空，重试需重新输入。输入期间开发者工具仍能读取输入框当前值，浏览器密码管理器是否保存由用户控制；不能保证清除 JavaScript 内存中的字符串。

此功能隐藏请求载荷中的原密码，不能阻止本机调试、恶意扩展或键盘记录，也不能替代 HTTPS 和证书信任。浏览器不支持安全加密时拒绝登录，不自动退回明文请求。原 `/api/auth/login` 保留供已有本机客户端兼容，网页不再调用；共享账号桥仍只在私有容器网络接收服务器解密后的凭据。密码存储、登录限流、会话 Cookie 和账号库保持原逻辑。

公网镜像必须基于安装了当前依赖锁文件的已测试网页镜像构建，旧基础镜像缺少加密库时会在构建阶段报错。开发机先在项目虚拟环境更新依赖；不要全局安装加密库。

## S3 模拟模式（仅供本分支本机试用）

设置 `DATAMARK_S3_MOCK=1` 后，本机可选择采集设备 `video/` 中的 AVI，并在隔离的模拟对象存储中浏览、标注和写回。管理员仍由 `zengl` 担任：所有有效标注账号都能领取未领取的项目并标注，只有管理员能在“账号管理”中开放或禁用每个标注账号的上传权限；新账号默认不能上传，管理员始终可上传。上传权限在服务端逐次核验，禁用后已登录账号也不能继续上传或发布。纯数字密码至少 8 位，其他密码至少 12 位；创建、重置和自行修改密码遵循同一规则。

账号可填写可选邮箱，由管理员在账号列表中查看；登录时可使用账号名或邮箱。邮箱不参与验证或找回密码。

上传人电脑运行本机服务，并通过页面打开操作系统文件选择窗口，在同一个 `video/` 文件夹中选中本次采集的 AVI；不选择同级身份 TXT。浏览器只接收文件名、大小、采集日期和选择凭据，不读取或上传原始 AVI 字节。本机服务直接从 U 盘或电脑原位置读取 AVI，转换为 480×270 的低码率 MP4，校验后才交给模拟对象存储，发布到 `daily/<采集日期>/<月日+采集人>/FPV/`。用户填写采集人，上传人和备注可留空；上传人留空时使用当前登录账号的姓名，实际操作账号始终单独记录，不能由表单覆盖。采集日期取视频文件名中最早的录制日期，不取上传当天；例如 `video/A09999_20261009204230_0000.avi`、采集人填写 `zengl`，目标为 `daily/20261009/1009zengl/FPV/A09999_20261009204230_0000.mp4`。采集人、上传人、实际操作账号和备注保存在采集目录清单中，浏览该目录时显示。目标采集目录已存在时拒绝覆盖。模拟对象、账号、项目和草稿位于被 Git 忽略的 `.local/s3-mock-app/`；原视频不被修改，默认也不连接 NAS 或真实 S3。

本机上传程序把压缩成品暂存在 `.local/s3-mock-app/.local/mock-upload-staging/`，模拟对象存储只接收经核对的 H.264 MP4 和采集清单；旧版通过网页传原始 AVI 的接口已停用。上传程序通过独立的发布接口与模拟存储衔接，真实 R2 使用下文的独立上传工具和公网配置；不能把 mock 测试视为真实桶验收。

标注员逐层进入 `daily`、采集日期、个人文件夹，选择完整项目；普通和倍速播放素材在开始标注前完整缓存到其浏览器的本机专用存储。普通视频直接使用模拟对象存储中的压缩 MP4，倍速视频、封面和悬停图片仍由准备流程生成。导出到云端后，当前勾选的场景、姿势、大类及自定义轴 JSON 写入同一采集目录的 `timeline/` 并读回核验，格式与 NAS 的 `timeline/` 一致。这里的签名链接只供本机测试，不是 AWS S3 链接。现有 Ubuntu 服务、Vercel 发布和 Cloudflare 解析均不使用此模式。

同一套服务代码通过部署配置选择新采集项目的来源，切换配置后需重启服务：内网现行部署默认 `DATAMARK_STORAGE_BACKEND=nas`；本机模拟服务默认 `DATAMARK_STORAGE_BACKEND=s3-mock`。要在本机验证两种来源的切换，先将 `DATAMARK_MOCK_NAS_ROOT` 设为这台电脑已经挂载、可读写的 NAS 数据根目录，再以 `DATAMARK_STORAGE_BACKEND=nas` 或 `s3-mock` 启动。页面只显示当前配置对应的新建项目入口，已有项目仍可从项目列表打开；每个项目保留创建时的来源，播放和 `timeline/` 写回始终走该来源。NAS 目录必须在指定根目录内，模拟对象不能通过 NAS 导入接口打开。此配置只对本机 mock 服务生效，不会把 NAS 开放到公网，也不会自动复制或迁移已有项目。真实 R2 通过独立公网服务接入，现行内网部署仍不接受将该配置改为 `s3-mock` 或 `s3`。 页面现在通过统一的 `/api/storage/sources` 和 `/api/storage/projects/open` 访问当前配置的采集目录；原 NAS 与 S3 模拟接口保留兼容，登录、领取权限和目录边界仍由服务端检查。

在已经安装项目内 Python 环境、前端依赖和 FFmpeg 的 macOS 开发机上，从项目根目录运行：

```sh
.venv/bin/python -m backend.auth --root .local/s3-mock-app
DATAMARK_S3_MOCK=1 FFMPEG_PATH=/opt/homebrew/bin/ffmpeg FFPROBE_PATH=/opt/homebrew/bin/ffprobe .venv/bin/python -c 'from backend.app import create_app; import uvicorn; uvicorn.run(create_app(), host="127.0.0.1", port=8766)'
```

首条命令仅在首次创建模拟管理员时运行，账号输入 `zengl`，密码在终端交互输入；FFmpeg 路径按本机实际位置替换。随后打开 `http://127.0.0.1:8766`，由有上传权的账号进入“新建项目”→“上传 AVI 视频”，点击“选择本机 video 文件夹中的 AVI”，在操作系统窗口选中本次采集的视频并填写采集人，等待本机压缩完成，再选择刚发布的文件夹。当前只处理 AVI；IMU 和心率数据不在本轮范围。选择后须保持 U 盘连接、AVI 文件不变，直到压缩完成；若文件变化或设备断开，任务失败且不会发布采集目录。`8766` 仅供本机 mock 使用，可与原有的 `8765` 服务并行。旧桌面只读测试入口可通过 `DATAMARK_S3_MOCK_SOURCE_DIR` 和 `DATAMARK_S3_MOCK_SOURCE_KEY` 继续启用；它不是新上传目录，也不会被自动迁移。真实 S3 接入时，本机上传程序仍须先压缩并校验，再把成品上传到 S3，不能让原始 AVI 经 Ubuntu 中转。真实 R2 的配置、直传和跨域检查见下文；部署前必须完成真实桶读写核验。

## 启动与停止

Windows 桌面快捷方式 **DataMark 启动或重启** 指向本项目的 `restart_local.py`：双击后先构建最新前端，再启动或重启本项目的 `127.0.0.1:8765` 后端并打开网页。前端网页由同一个本机服务提供；连续点击启动入口时会等待已有启动操作，不重复启动服务。新启动的后端正常退出后再重启；旧启动器会核验本项目进程身份后停止，其他应用占用端口时不会停止该应用。启动日志保存在 `.local/logs/restart-local.log`。此入口只操作本机，不推送代码、不部署云端。

Windows 本机已配置项目内运行环境时，双击项目根目录的 **启动标注平台.lnk**；macOS 本机已配置项目内虚拟环境、前端构建和 FFmpeg 工具时，在项目根目录运行 `.venv/bin/python launch.py`。两种方式都会启动后台服务并自动打开浏览器。关闭最后一个标注网页后，服务会在约 15 秒后自动退出，并停止未完成的预览生成；下次打开可继续准备。刷新页面、网页在后台或其他标注标签页仍打开时不会退出。已有服务时再次启动只打开网页，不重复启动服务。

服务停止后，普通浏览器无法仅靠访问网址唤起本机程序；再次使用请在 Windows 双击启动快捷方式，或在 macOS 重新运行启动命令。日志保存在 `.local/logs/server.stdout.log` 与 `server.stderr.log`。

更新平台代码后，刷新网页只会更新页面，不会重启后台服务。先让进行中的导入／准备任务完成，再关闭所有平台网页，等待约 15 秒后按对应系统的方式重新启动，前后端即可一起使用新版本。已完成的缓存和标注会保留。

Windows 首次重新安装或更新源码后，先运行 **setup.cmd**。脚本使用本机已有 Python 和 Node，创建 `.venv`、按锁文件安装依赖、校验 FFmpeg 下载并构建前端；不修改永久 PATH、用户级包管理配置、系统服务或 PowerShell 执行策略。命令行方式：

```powershell
.\setup.cmd
.\启动标注平台.lnk
```

首次安装时，`setup.cmd` 会在控制台提示创建管理员账号和密码；密码输入不会显示，也不会写入命令历史。若使用现有环境手动更新，可运行 `.venv\Scripts\python.exe -m backend.auth` 创建首位管理员，再启动平台。没有有效管理员时启动程序会拒绝提供标注服务。不要在聊天、代码或文档中填写密码。

## 账号与项目权限

登录后才能读取项目、预览素材、保存草稿或导出。管理员总览全部 NAS 项目，可新建标注账号、停用或启用账号、重置密码，并在需要时调整项目领取人。标注员不必等待管理员分配：从 NAS 选择完整采集目录后，未领取项目由第一位标注员领取；其他标注员不能打开或重复导入其中视频。每个项目只有一位标注员领取，管理员仍可查看和编辑。管理员与领取人同时打开项目时，页面显示其他在线编辑者；草稿保存还核对项目版本，旧版本不会覆盖新版本。突然断开的在线提示约 45 秒后过期。标注员可对自己领取的项目跳过或恢复准备失败的视频、导出 JSON 到云端。关联原目录和重命名仍由管理员操作。停用账号或重置密码会立即撤销该账号已有登录。任何用户都可在页面上修改自己的密码，修改后需要重新登录。

密码采用带独立随机盐的 scrypt 哈希保存于 `.local/auth.sqlite3`，登录会限制连续失败次数。登录使用 12 小时会话，浏览器只持有不可由 JavaScript 读取的会话 Cookie；修改接口另检查页面安全令牌和来源。本机启动器仍只监听 `127.0.0.1`；Ubuntu 内网部署按下文配置独立 HTTPS 入口。公司邮箱验证码暂缓；公网入口待独立 S3 业务服务具备后启用，不要把本机或内网 NAS 服务端口映射到公网。

每次保存草稿时，服务端根据当前登录账号记录标注的创建者、创建时间、最近编辑者和最近编辑时间；客户端提交的这些字段不能覆盖服务端记录。选中标注可查看其归属，页面可打开编辑历史查看新增、修改、删除和撤销引起的变更。旧版标注没有可验证的操作者，显示为未知。浏览器内尚未提交的自定义事件输入按账号隔离；有未保存编辑时会阻止直接退出登录。停止服务后备份 `.local/annotations.sqlite3` 与 `.local/auth.sqlite3`，两者分别保存草稿及编辑历史、账号与项目分配；不要提交到 Git。

验证环境：Python 3.14.6、Node 24.18.0。运行时记录见 `runtime-manifest.json`，Python 全部依赖锁定在 `requirements.lock.txt`，前端依赖锁定在 `frontend/package-lock.json`。`setup.ps1 -SkipFrontend` 只检查／安装后端和 FFmpeg，不重建前端。

## Ubuntu 内网部署

`deploy/compose.intranet.yaml` 部署网页服务和独立 HTTPS 网关，原有 `deploy/compose.yaml` 仍只负责视频处理服务。该内网网关端口只绑定 `DATAMARK_BIND_IP` 指定的 Ubuntu 内网地址；网页容器不发布端口。请同时在主机防火墙及网络边界只允许授权内网访问该网关的 443，不要将这个内网入口映射到公网。内网网页只允许浏览和导入容器内 `/mnt/nas/homes/datacollection` 下的采集素材；更换采集根目录时须同步修改 Compose 中的 `DATAMARK_SOURCE_ROOT`，不能指向整个 NAS。部署需要 Ubuntu 已安装 Docker Compose、NAS 已挂载到本机，并确认服务 UID/GID `1000:1000` 对采集素材有读取权限、对标注输出及缓存目录有写入权限；读取和写入须分别验证。

在 Ubuntu 项目目录复制 `deploy/intranet.env.example` 为 `deploy/intranet.env`，填写实际值：`DATAMARK_HOST` 是浏览器访问的内网 IP，`DATAMARK_BIND_IP` 是服务器持有的 RFC1918 局域网网卡 IP，`DATAMARK_HOME` 是应用持久化目录，`DATAMARK_NAS_MOUNT` 是已挂载的 NAS 根目录，`DATAMARK_WEB_IMAGE_TAG` 是本次发布标识。前两项使用 IP 直连时通常相同。已核实 `relty-server` 的 `192.168.2.126` 是固定内网地址，`192.168.2.25` 是同一服务器的动态有线地址；在该服务器部署时使用前者。配置文件不存放密码，实际配置文件已被 Git 忽略。先核对 NAS 挂载和目标目录，再执行：

```sh
install -d /home/relty/services/datamark-web/caddy-data /home/relty/services/datamark-web/caddy-config
docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml config --quiet
docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml build web
```

完成下面的数据迁移后执行 `docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml up -d`。若从空库开始，先创建与 `DATAMARK_HOME` 一致、归 UID/GID `1000:1000` 所有的 `state/`，再通过 `docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml run --rm --no-deps web /opt/venv/bin/python -m backend.auth` 交互创建管理员。管理员密码不写入配置文件或命令历史。启动后检查两个容器健康状态，并从授权内网设备访问 `https://<DATAMARK_HOST>/api/health`、登录、项目分配、预览、草稿保存、导出和 NAS 写回。只有实际读回本次所选轴的全部 `timeline/` 文件后才能确认 NAS 写回成功。

网关使用内部证书颁发机构自动签发 HTTPS 证书。首次启动后，从持久化的 `caddy-data/caddy/pki/authorities/local/root.crt` 获取公开根证书，按公司设备管理流程导入每台访问设备的受信任根证书库；私钥和整个 `caddy-data` 目录不得分发。浏览器未信任根证书前，不要通过忽略证书警告输入账号密码。 macOS 的 Chrome 不接受按单个主机名或 IP 限定的钥匙串根证书信任；须经授权在用户钥匙串中仅为 SSL 用途信任经过指纹核验的 NAS 内部 CA，其信任范围覆盖该 CA 签发的 HTTPS 证书。导入后完全退出并重开 Chrome，再检查连接安全状态；每台访问设备分别配置信任。持久化备份应覆盖应用 `state/` 中的两个 SQLite 数据库和项目播放缓存，以及 `caddy-data/`；恢复时先停服务，恢复完整目录后再启动并验证登录与项目读写。

内网网关默认使用 443。手动将当前分支作为内网服务部署到 10443 时，在持久配置中同时设置 `DATAMARK_HTTPS_PORT=10443` 和 `DATAMARK_ORIGIN_PORT_SUFFIX=:10443`，并用 `https://<DATAMARK_HOST>:10443` 访问。切换前备份现有配置与两个 SQLite 数据库，然后替换现有 Compose 服务，避免两个实例同时写同一项目与 NAS；账号和项目继续使用原持久目录。关闭路由器上的 10443 端口映射，不能将此 NAS 服务作为公网入口。

### Jenkins 自动发布

公网发布只接受与 `origin/feat/s3-mock` 完全一致且无已跟踪文件修改的提交。它复用 `/home/relty/services/datamark-public-setup/runtime.conf` 及原有挂载目录，不读取或复制 R2 凭据内容，不挂载 NAS 到公网 API，也不重建公网网关。更新前停止公网 API，将公网项目、任务数据库和结果目录完整备份，并在线备份共享账号库；备份保留在该服务的 `backups/` 下。账号服务和 API 更新后，必须通过容器健康检查、受信 HTTPS 就绪检查与加密登录接口检查，才更新持久镜像配置和 `current`。失败恢复旧镜像、配置与发布链接，不自动覆盖仍在使用的数据库。数据库模式不兼容时仍需人工评估。Vercel 继续独立自动发布，因此发布期间前后端可能存在短暂的版本时间差。

`main` 保留为 Ubuntu 默认的 443 发布分支。当前 `relty-server` 的 Jenkins 任务使用 **Pipeline script from SCM**：仓库地址 `git@github.com:Relty-Dynamic/Data-Annotation.git`，分支指定 `feat/s3-mock`，脚本路径 `Jenkinsfile`，只在同机的 `built-in` 节点运行。Jenkins 轮询该远端分支；每次新提交先构建并测试，再分别自动更新 10443 内网 NAS 服务和 8443 公网 S3 后台。检出提交必须与 `origin/feat/s3-mock` 完全一致，发布脚本还会再次核对分支、端口、内网来源配置和正在运行的服务；其他本地开发分支不会触发此发布流程。S3 模拟模式须在本机明确启用；通过页面上传采集目录时无需预设桌面测试视频路径，也不会随分支构建自动启用。

首次启用前，由 `relty` 在 Ubuntu 上把当前发布目录中的 `deploy/intranet.env` 复制到持久目录 `/home/relty/services/datamark-web/intranet.env`，权限设为 `600`，并将 `/home/relty/services/datamark-web/current` 链接到已运行的发布目录。配置文件、数据库、证书和 NAS 素材始终留在仓库外。Jenkins 与网页容器使用同一台主机上的 `relty` 账号，且该账号已有 Docker 权限；流水线不会创建管理员或更改系统服务。

`feat/s3-mock` 的新提交在镜像构建中运行前端测试和构建，再在隔离容器中运行后端测试；测试容器以非 root 身份运行，`.tmp` 与 `.local` 使用临时内存挂载，迁移测试的账号和数据库样例不会连接生产持久目录，容器退出后自动清理；随后构建公网 R2 镜像并运行公网、账号、加密登录、任务和部署回滚测试；全部通过后，并行调用 `deploy/ci-deploy-intranet.sh s3-mock-10443` 与 `python3 deploy/ci_deploy_public.py`。两边独立检查和回滚，一边失败不会阻止另一边尝试发布，但任意一边失败都会使流水线失败。同一个脚本不带参数时仍只接受 `origin/main` 和 443；传入 `s3-mock-10443` 时只接受 `origin/feat/s3-mock` 和 10443，不能从其他本地分支发布。它从已构建且测试通过的提交创建独立发布目录、在线备份两个 SQLite 数据库、仅更新 DataMark 的 Compose 服务，并通过内网证书验证对应端口的健康接口。发布会短暂重启网页服务；健康检查失败会尝试恢复先前容器版本，`current` 链接仅在健康检查成功后切换；成功后也会把持久配置中的网页镜像标识更新为已验证的提交，避免后续重启恢复旧镜像。备份存放于 `backups/<提交>-<时间>/`，不会自动删除；数据库模式不兼容时须人工评估恢复，不能直接覆盖仍在写入的数据库。内网发布脚本要求旧公网来源配置为空，并要求旧公网网关已停止，防止 NAS 服务随发布重新暴露。Jenkins 的测试通过和健康接口正常不等于真实项目的 NAS 写回验收；仍需用授权账号实际标注并读回本次勾选写回的全部时间轴文件，同时确认未勾选轴的已有文件未被覆盖或删除。

容器的 Python 安装保留 600 秒总时限及失败即停止的行为；Jenkins 在该 Ubuntu 节点使用清华 TUNA 的 HTTPS PyPI 镜像，按现有锁文件安装 wheel，并执行 `pip check`。Docker BuildKit 的专用 `datamark-pip` 缓存供网页、处理服务和独立 R2 镜像复用，缓存不进入最终镜像，不修改宿主机 pip 配置；清除构建器缓存或换机器后仍需重新下载。手动构建默认使用官方 PyPI，可通过 `--build-arg DATAMARK_PYPI_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple` 选择同一镜像；如镜像缺少锁定版本，安装会明确失败，不降级版本、不忽略依赖，也不跳过测试。

### Vercel 公网页面与 S3 服务

公网与内网使用同一个 Ubuntu 账号数据库，用户直接用同一套账号密码登录，无需选择账号属于 NAS 或 S3；本机账号保持独立。账号新增、重置密码、停用及权限管理仍在内网进行，公网实时验证同一数据库，重置或停用会使公网旧登录失效。两个入口分别登录，Cookie 不跨主机共享，不要求重新创建账号。账号不存放在 S3。

在 S3 接入前，公网服务 `backend.public_setup:create_app` 提供共享账号登录、查询登录状态、退出，以及 HTTPS、跨域和 WebSocket；素材及标注业务接口仍返回 503。健康接口保持 `mode: public-setup`、`ready: false`、`storage_ready: false`，共享账号连接成功后 `accounts_ready: true`。登录后页面显示账号已登录及 S3 未配置，不进入尚不可用的工作台，不能据此报告 S3 可用。

部署使用 `deploy/compose.public-setup.yaml`、`deploy/Caddyfile.public-setup` 和 `deploy/Dockerfile.public-setup`，与 10443 NAS 服务分别运行，公网默认 8443（容器内部 443）。`accounts` 服务只连接私有 Docker 网络，不发布端口；通过 `DATAMARK_SHARED_ACCOUNT_STATE` 挂载现有内网 `state/`，仅使用其中的 `auth.sqlite3`，不复制或新建账号库，不提供项目、素材或文件接口。公网 `api` 通过固定内部账号接口访问，自己不挂载账号状态、业务数据库或 NAS 目录。SQLite 的 WAL/SHM 与账号库使用同一持久目录；不得只挂载或复制单个数据库文件。账号服务启动必须找到现有数据库及管理员，缺失时拒绝启动；服务故障时拒绝登录，不回退到另一套账号。

其他部署参数为 `DATAMARK_SETUP_IMAGE`、`DATAMARK_PUBLIC_BIND_IP`、`DATAMARK_PUBLIC_PORT`（默认 8443）、`DATAMARK_PUBLIC_API_ORIGIN`（默认 `https://api-annotate.reltydynamic.com:8443`）、`DATAMARK_TLS_DATA` 和 `DATAMARK_DNS_TOKEN_FILE`。TLS 使用该域名现有的 Caddy 托管目录，DNS 凭据只挂载给网关，不写入代码或前端。企业网关两层转发均使用 8443 时，Vercel 的 `VITE_DATAMARK_API_ORIGIN` 填写带 `:8443` 的 API 地址。生产前端跟踪 `feat/s3-mock`，该分支更新会自动发布正式域名。后续真实 S3 业务后端继续使用此共享账号服务，项目和草稿按权限及存储来源隔离；仅填写桶名称不会启用上传或标注。

内网和公网使用同一套标注代码，但按部署配置选择存储：内网服务使用 NAS，公网服务将使用私有 S3。Vercel 继续托管静态页面，Cloudflare 只提供 DNS 解析；当前公网入口使用 `https://api-annotate.reltydynamic.com:8443`。内网和公网共用 Ubuntu 上同一个账号数据库，同一账号可登录两个入口；项目和草稿仍须按权限及存储来源隔离，本机独立账号保持不变。公网业务服务不能挂载 NAS。未启用下面的 R2 配置时，公网素材与标注接口仍不可用；不要将内网 NAS 服务接到公网域名。先前的 `10443` 路由器端口映射已由管理员关闭，仓库内的 NAS 发布脚本也不再启动旧公网网关。

本分支的 S3 模拟模式只在本机运行，用于验证选择 `video/` 中的 AVI、采集人和上传人记录、视频压缩、按 `daily/<采集日期>/<月日+采集人>/FPV/` 浏览、标注及写回 `timeline/`。本机上传程序从选中的原位置读取 AVI，压缩后才交给模拟对象存储；原始 AVI 不经网页传到服务端。真实 R2 实现私有桶访问、经业务账号授权的对象清单与下载、分片续传、条件版本写回及读回核验，但必须完成下面的部署与真实桶验证。模拟模式的签名链接和测试结果不等于真实 S3 验收。

将来公网部署具备真实 S3 接口后，Vercel 项目的 Root Directory 为 `frontend`，框架为 Vite，构建命令 `npm run build`，输出目录 `dist`；构建变量 `VITE_DATAMARK_API_ORIGIN=https://api-annotate.reltydynamic.com:8443` 必须指向该公网业务接口。浏览器登录、领取项目、下载普通与倍速精简视频到本机专用存储、标注并写回 S3 的全流程，必须从外网用授权账号实测。账号保留在 Ubuntu 数据库中，不存放到 S3；内网 NAS 的草稿和 `timeline/` 不会自动迁移到 S3。旧本机项目同步功能现在没有默认公网地址，只有显式设置 `DATAMARK_CLOUD_API_ORIGIN` 才尝试连接；现有同步接口面向 NAS 内网服务，不属于 S3 上线流程。

### 真实 Cloudflare R2 接入

R2 接入只作用于独立公网服务。NAS 和普通本机启动不设置这些变量，继续使用原来的账号、项目和缓存规则。真实桶连接、部署以及从外网完成上传／标注／写回尚需现场验收；以下是已实现的配置与操作方式。

公网后端设置 `DATAMARK_R2_CONFIG` 为受保护 JSON 文件的绝对路径，设置 `DATAMARK_R2_STATE` 为独立持久目录的绝对路径，并保持共享账号服务启用。配置文件只包含 `endpoint`、`bucket`、`access_key_id`、`secret_access_key`；`endpoint` 使用账户级 `https://<账户ID>.r2.cloudflarestorage.com`，不附加桶名，区域由程序固定使用 `auto`。Linux 文件须由容器运行账号读取且权限为 `600`，上级目录使用 `700`。密钥不进入环境变量、Git、前端、聊天或日志。Public URL 不作为下载入口；桶的公开访问设置须另行核对，使用签名链接不能撤销已经开启的匿名访问。

在 Ubuntu 的项目运行环境内，先检查连接与目录读取，再明确执行读写探测与跨域配置：

```sh
/opt/venv/bin/python -m deploy.check_r2 --config /run/secrets/r2.json
/opt/venv/bin/python -m deploy.check_r2 --config /run/secrets/r2.json --probe --cors-origin https://datamark.reltydynamic.com
```

探测只在随机 `_datamark-checks/<编号>/` 创建小型检查对象，核验条件创建、冲突拒绝和读回，保留对象供核查，不覆盖已有采集数据。跨域配置只替换本应用命名的规则，保留其它规则；额外前端域名须逐个传入 `--cors-origin`，不允许任意来源。连接成功不等于已验证所有业务权限。

Ubuntu 上还可运行完整技术验证（需 FFmpeg、独立临时目录且可用空间超过 512 MiB）：

```sh
/opt/venv/bin/python -m deploy.verify_r2_workflow --config /run/secrets/r2.json --confirm-test-writes
```

该命令生成测试视频，使用临时账号数据库，经实际公网应用接口执行本机压缩、桌面缓存保留、R2 签名分片上传、草稿保存、JSON 写回重开、版本冲突拒绝及普通／倍速视频和图片下载核验。R2 请求使用真实凭据，但对象全部限制在随机 `_datamark-checks/<编号>/`，不发布正式 `daily/` 项目；检查对象保留供核查，不删除已有对象，不读取生产账号，不切换服务。临时桌面目录用于验证文件及内容一致性，不能代替真实 macOS／Windows 浏览器目录授权和外网用户验收。

部署使用经过完整测试的镜像，将 `deploy/compose.r2-public.yaml` 叠加到原 `deploy/compose.public-setup.yaml`；若任务管理原已启用，还须保留 `deploy/compose.tasks-public.yaml`。配置 `DATAMARK_R2_CONFIG_FILE` 为宿主机密钥文件，`DATAMARK_R2_STATE_DIR` 为独立的公网持久状态目录；后者保存公网项目、草稿、上传进度与可再生成的媒体缓存，不是 NAS 状态目录。只有公网 API 加入存储出站网络，NAS 挂载与账号服务的私有网络保持原配置。`deploy/Dockerfile.r2-public` 可在现有已测试基础镜像上构建独立公网镜像，也可使用完整的 `deploy/Dockerfile.web` 构建本次提交。切换前用 SQLite 在线备份保存公网及任务数据库、保留旧镜像和覆盖文件；回滚时停止公网 API，恢复旧镜像与原覆盖文件，保留新状态目录供排查，不覆盖正在运行的数据库。

启动时先核验桶连接；缺少密钥、权限或持久目录会拒绝启用 R2，不创建另一套账号或转用 NAS。成功启用后健康接口为 `mode: s3`、`storage_backend: s3`；只有共享账号与 R2 当前均可用时才显示 `ready: true`。不配置 R2 时仍是原 `public-setup` 行为。

上传弹窗分为“FPV / 完整采集”和“仅 IMU”，文件清单和选填备注折叠，素材选择与采集信息在宽屏并排、窄屏上下排列，支持 Chrome 和 Edge。

- 只传 FPV：选择本机 `FPV/`、`video/` 或仅含 AVI 的文件夹，取消“上传前生成姿势预标注”，沿用压缩、播放缓存生成及上传流程。
- 同时上传：选择包含 FPV 和 IMU 的采集父文件夹，FPV 在本机压缩、IMU 原样上传；需要预标注时勾选预处理并确认胸部和大腿设备，未勾选则保留上传已有预测。
- 只传 IMU：选择“仅 IMU”，选择 IMU 文件夹或含 `IMU/` 子目录的采集父文件夹，填写实际采集日期和采集人。仅上传有效 IMU 数据文件，支持 `.wplay` 和现有数据格式，不需要视频、不压缩、不运行视频校时预标注。

两类素材均归到 `daily/<采集日期>/<月日><采集人>/`，例如 `daily/20261001/1001lixin/FPV/` 与 `IMU/`。分次上传时，必须填写完全一致的采集日期、采集人；FPV 日期仍从视频名读取，IMU 日期显式填写，不使用上传当天。任意先后顺序均可补齐另一类素材，同类已有发布结果不覆盖；同一请求可续传。完整采集若与已上传 IMU 重叠，IMU 的逻辑路径、大小、摘要必须全套一致，否则拒绝混合。

独立 IMU 使用 `imu.manifest.json`，不修改既有视频 `manifest.json`、项目素材标识或标注；仅 IMU 目录可以浏览，但不能导入视频标注。共同的 `capture.identity.json` 和 `imu.files.json` 使用条件创建，防止并发上传写入不同采集身份或 IMU 内容。所有文件仍须通过大小、完整内容摘要及权限核验后才能发布，原始数据和既有标注不删除。此功能需更新公网后端与本机组件；后端通过 `s3-imu-upload-v1` 能力声明开放“仅 IMU”，旧版服务上该入口不可用。NAS 领取、内网缓存及旧命令行上传入口不变。

上传窗口采用与任务管理一致的深色卡片、表单和进度样式；本机组件报告任务 `ready` 且无待执行命令、处理中状态或错误时，弹窗提示“上传成功”及采集目录。同一组件的同一任务在本页面内只提示一次，轮询和关闭重开不会重复弹窗；刷新页面后可再次提示。压缩或上传到 100% 并不单独表示发布成功。

文件传输完成后，组件显示“正在校验并发布采集目录”，该请求单独等待最多 600 秒，其余接口继续使用原超时。连接中断或网关返回 502／503／504 时，组件通过仅允许上传者本人且仍有上传权限的状态接口核对服务端持久结果；只有 `ready` 才确认成功。无法确认时明确提示结果未确认和可续传，不把连接超时直接当作上传失败。重复完成已发布任务直接返回原结果，不重新下载校验或覆盖目录。此修复须同时更新公网后端与本机组件；NAS 流程不变。

公网上传与“导入已有视频”是两个步骤：上传将本机采集数据放入 S3；导入只将已有 S3 采集目录登记到平台，之后登记采集信息、质检、分配任务。NAS 内网及普通本机 NAS 模式保持原流程，不增加原视频上传功能。管理员默认有上传权限，组长在创建或保存角色时默认获得上传权限；管理员仍可在账号管理中单独开放或关闭普通账号的上传权限。上传服务始终核对账号当前的 `can_upload`，不以客户端显示的角色代替权限检查。

登记表的“采集人姓名”自动读取 S3 上传清单中填写的采集人，切换采集文件夹时同步更新，允许手动修正；普通列表刷新不重置已修改的姓名。旧素材或 NAS 没有该信息时保持空白，由用户填写，不从文件夹名推断。仍保存到兼容字段 `collector_id`，不要求采集人拥有平台账号。S3 全套播放缓存统一由上传者本机生成：普通压缩视频、20 倍速视频、JPG 缩略图和每秒采样的悬停图集。组件复用现有生成格式，并将全部成品保留在桌面 `dataMarkProject/<采集目录名>/`，再将普通视频及关联缓存上传到 S3 对应采集目录的 `FPV/` 和 `FPV/cache/`。服务端核对文件内容摘要、大小、完整清单、倍速时间与 JPG 格式后才发布目录；进入传统项目或任务标注工作台时，只下载并复用上传缓存，不再调用 Ubuntu 生成视频或图片。具有完整上传缓存清单的 S3 任务标注和复核直接使用上传时已核验发布的缓存清单与短期签名地址，不再为每个账号的工作台重复下载一套 Ubuntu 播放缓存。浏览器先校验授权目录中的本机缓存，有效文件跨账号和任务直接复用，不重复压缩或下载；仅下载缺失或校验失败的文件，全部校验、载入完成后才能标注。已存在的完整旧播放缓存允许继续复用；旧采集目录没有完整缓存时明确提示上传者使用新版组件上传到新采集目录，保留原目录及标注，不自动覆盖或在服务端补生成。NAS 流程保持原样。此变更需要同时部署公网后端并更新上传者本机组件，旧组件上传的素材不会自动拥有完整缓存。

公网网页有上传权的账号可在“任务管理 → 素材与质检”，或“新建采集项目”中点击“上传采集文件夹”。上传弹窗始终留在原 DataMark 页面：先检测本浏览器关联的本机组件，未连接时显示 macOS／Windows 的复制安装命令，已连接时直接选择文件夹、填写采集人并压缩上传。浏览器无法仅凭网络检测区分“未安装”“未启动”和“网络中断”，因此提示为“未检测到正在运行的本机组件”，不把超时声称为组件不存在。

网页安装命令由当前公网 API 地址生成，**新电脑只从 DataMark 的 HTTPS 入口获取完整安装包，不再直接访问第三方依赖站点**。提供 macOS Intel、macOS Apple Silicon 和 Windows x64 三套包，内含 Python 3.14.6、当前组件源码、全部锁定依赖和 FFmpeg／FFprobe，不需要预装 Python、Node、Git、uv 或管理员权限。命令自动识别系统、显示下载进度、断点续传并校验完整 ZIP 的 SHA-256，然后在桌面 `DataMarkUploader/` 内创建 `.venv`，用 `pip --no-index --find-links` 从包内安装，运行 `pip check` 和压缩工具启动验证。Python 原始发行包另核对固定官方摘要，源码拒绝越界路径和符号链接；离线目录只忽略 Finder／Explorer 自动增加的普通 `.DS_Store`、`desktop.ini`、`Thumbs.db` 元数据文件，清单内文件仍逐个校验，额外代码、伪装名称和符号链接仍拒绝；macOS 沿用 Martin Riedl FFmpeg 9.0.2，Windows x64 沿用 Gyan FFmpeg 9.0.1，包中记录来源和附带许可。缺包、摘要不符或验证失败立即停止，不降级或跳过检查。不修改永久 PATH、注册表、系统服务、全局 Python、包管理配置或 PowerShell 执行策略；Windows 恢复当前进程原环境变量。旧源码和 bootstrap 接口保留兼容，旧安装命令本身仍可能使用原外部下载源，须使用新页面命令更新。

组件连接时报告源码版本，网页在新版本可用且没有正在执行的任务时显示更新命令；不打断已有上传。上传弹窗提供“下载完整离线安装包”和校验值。可在其他电脑下载并核对 SHA-256 后拷贝、解压，在解压目录打开终端，使用弹窗提供的离线命令安装；安装阶段不访问网络。命令携带原浏览器和当前平台地址，完成后仍在原浏览器打开关联页面。真正上传、预标注和账号关联仍需能够直连平台及授权 S3 地址；安装包解决依赖下载，不改变网关回流或 S3 网络通路。

三套完整包随独立公网镜像构建：构建机下载并校验固定版本官方运行包和工具，按 `requirements.uploader.lock.txt` 收齐组件所需依赖；它与服务端锁文件使用相同版本，组件不安装服务端专用 S3 SDK 和登录加密库，服务端锁文件及登录加密行为不变。任何平台缺包均使公网镜像构建失败，不触发公网发布；内网 NAS 镜像不增加安装包。官方文件和依赖使用 BuildKit 专用缓存，不写宿主机全局配置，也不向用户开放构建缓存。构建下载会显示文件名、已下载／总大小与速率，每约 10 秒输出一次进度；连接或读取中断后保留断点，最多尝试三次，每个文件总下载时间上限 15 分钟。服务器不支持断点时安全重下，断点响应异常或完整摘要不符时不发布。已完成的运行包、工具及离线依赖经摘要复核后复用，不因只改源码而再次从外网下载。最终包位于公网镜像 `/app/uploader-dist/`，源码或锁文件变化时必须重建；接口仅发布来源版本和摘要均核验通过的包，缺失或过期时安装接口返回 503。完整包和下载缓存不能提交 Git。

安装后本机组件主动通过 HTTPS 连接独立公网后端，并打开原 DataMark 正式页面完成一次性关联。已有网页登录状态可直接复用，账号密码、通用会话 Cookie 和 S3 密钥不发给组件。网页生成的命令包含当前浏览器类型（Chrome／Edge／Firefox／Safari），组件仅在该浏览器中打开关联页面，不调用系统默认浏览器。未携带浏览器信息的旧命令、未知浏览器或指定浏览器启动失败时，终端给出一次性关联地址，用户须在原来已登录的浏览器打开；组件本身没有第二套登录。关联信息放在 URL fragment 中，页面在登录检查前移除 fragment，不进入服务器访问日志或安装命令；一次性关联 5 分钟有效，成功后立即失效。网页仅保存公开组件 ID，后台只在内存中保留组件与父会话关联，单个关联最多 12 小时；服务重启、父会话退出或失效后需重新关联。公网 API 当前以单进程运行，此内存关联不能直接用于多进程部署。

网页与本机组件不直接跨域连接 localhost，不需要安装浏览器扩展、信任本机自签证书或降低浏览器安全设置。网页通过原 HTTPS API 发起“选择文件夹／开始压缩上传”并读取进度，组件主动轮询接收指令；文件夹始终由本机系统窗口选择，不接受来自网页的任意本机路径或系统命令。组件令牌只允许素材上传及自己的控制通道，不能调用项目、账号或任务接口；后台逐次验证父会话及当前上传权限，退出登录或关闭权限会阻止继续完成及发布。视频压缩和原数据读取仍在上传者电脑，成品与附属数据经签名地址直传 S3，Ubuntu 不接收原始视频。

安装命令同时也是后续的启动／更新命令。请保持组件终端开启；关闭上传弹窗不会取消后台任务，重新点击上传可查看进度。源码旧版本保留在组件目录的 `.tmp/`，`.venv`、工具、缓存与本机状态独立保留。压缩缓存继续写桌面 `dataMarkProject/<采集目录名>/`，不会与组件安装目录混用。NAS 内网和普通本机 NAS 不安装此组件、不开放这些接口。

NAS 精简普通视频与本机 S3 上传共用同一套压缩参数：H.264、480×270、视频 256 kbps、音频 AAC 32 kbps、保留原帧时序；均保留输入时间戳，再以视频起点归零音频并按视频时长裁切，保留原本的音画相对延迟。倍速视频及 JPG 继续复用现有共同生成流程。不同 FFmpeg 版本、机器和线程配置下，不承诺编码文件逐字节一致。

上传协议本身不要求 VPN；本机必须能够连接公网 API 和签名 S3 地址，完整上传是否直连成功仍取决于当前网络。本机上传组件、旧上传窗口和命令行上传的 API、IMU 与签名 S3 请求均明确直连，不继承 HTTP／HTTPS／SOCKS 代理环境设置；不修改系统代理或关闭其他软件。安装命令和完整包下载同样显式直连。直连失败会报错，不自动切换代理；实际可达性仍需在国内网络分别验证 API 与 S3，不能仅凭小请求成功认定完整上传已通过。网络客户端初始化失败会返回明确的 JSON 错误，不保留半登录状态；页面遇到非 JSON 服务器响应时显示 HTTP 状态及检查提示，不显示原始响应、堆栈或再次抛出 JSON 解析错误。更新依赖后须重启本机上传助手并刷新窗口。

在本机窗口中登录、选择采集根目录（或直接选择 `video/`／`FPV/`）、填写采集人及选填上传人和备注、确认文件清单后开始压缩上传。窗口显示采集日期、S3 目标、压缩进度、正在上传的文件及最终结果；中途关闭网页不会取消后台任务，重新打开同一窗口可查看进度，退出账号或重新选择目录须等当前任务结束。单机同一时刻只允许一个上传任务。原视频、缓存、标注和内网 NAS 服务均不因上传被删除或迁移。

本机从原位置读取 AVI，压缩为 H.264 MP4，先在桌面 `dataMarkProject/<采集目录名>/` 保留普通压缩缓存，再通过短期签名分片链接直接上传 R2。密钥始终留在 Ubuntu；原始 AVI 不经过 Ubuntu。上传状态保存在独立公网数据库中，重新运行相同选择可复用已上传分片；过期分片任务可重新建立。权限在服务端逐次检查，撤销上传权后不能继续完成或发布。

新版组件对不超过 16 MiB 的文件使用一次签名 PUT，大文件继续使用 16 MiB 分片；最多同时传输 3 个文件、共 3 个对象／分片请求，连接复用。失败重试重新查询已完成分片，不重复计入进度；界面按上传字节显示百分比、已完成文件数和本次传输平均速度，压缩、上传、核验分别显示阶段进度。

所有成品均按大小、SHA-256、实际编码及时长验证，最后才发布采集清单；中断文件不会成为可领取的采集目录。新版组件请求后台核验并轮询结果，不保持一个持续数分钟的 HTTP 请求。服务端最多并行核验 2 个任务，每任务最多 3 个文件，排队和执行任务合计最多 8 个；各文件锁彼此隔离，慢任务不持有全局上传锁。

核验回读中，至少 8 MiB 且具有对象版本号的文件按 4 MiB 分段读取，每文件最多 4 路、所有核验任务共用最多 6 路下载请求；每段固定对象版本并验证返回区间及长度，合并后仍验证完整 SHA-256。中断保留已完成分段及其本地摘要，恢复时重新核对；损坏分段重新下载，最终摘要不符时丢弃该文件的分段缓存，原文件不覆盖。界面同时显示通过文件数和已读取 MiB，尚未读完一个大文件也能看到进展。

核验仍完整读取文件、验证摘要和媒体格式；按对象 ETag 保存已通过的检查点，重启后须由同一账号重新授权恢复。对象版本改变时重新下载并检查，失败保留已上传内容与进度，全部通过且账号仍有权限时才发布采集清单。旧组件仍可调用原同步核验和分片接口；使用新流程需同时更新公网后端与本机组件。

公网后端声明 `s3-upload-pipeline-v1` 后，新版本机组件采用整条流水线：预标注与压缩并行；每段普通视频压缩完成后立即生成对应播放缓存，并开始该段上传及提前核验，不等待全部视频压完。每次最多运行一个普通编码任务、一个缓存构建任务和一组上传任务；后台核验继续遵守上述资源上限。第一段携带现有 IMU／HEART／prediction 附件，新生成的预测在最终收尾时加入。提前核验仅保存内部状态与检查点，不发布 `manifest.json`，不能登记、分配或标注半成品；全部选定视频、缓存、附件及所需预标注成功后才一次性发布完整采集。服务端按对象版本、大小、摘要和验证规则复用已完成的核验，改变时长或类型不能复用旧证明。旧组件沿用原有完整上传接口，不会误发布单段采集。

界面持续显示整组视频已核验段数；百分比按已核验视频计算，完整发布之前最多 95%，不再把单段 9 个文件传完显示为整组 100%。IMU 提交单独显示本机发送字节与等待服务端确认，只有收到成功响应才显示已确认；每次网络写入最多等待 15 秒、响应最多等待 30 秒，单文件整体发送最多 15 分钟，并在每个传输块之间检查其他步骤是否失败。任何并行步骤失败时立即显示错误，不等慢请求结束再变更界面；收尾仍等待实际工作线程退出，期间不能开始第二次任务。组件仅记录任务编号、错误类型和经过筛选的说明到其私有 `upload-errors.jsonl`，不记录签名链接、凭据或原始异常文本。

一次操作内原素材摘要按文件身份共享计算，压缩重试仍重新核对原素材。组件在自己的 `.local/upload-pipeline-index/` 只保留恢复索引；媒体仍位于桌面 `dataMarkProject/<采集目录名>/`。同素材、同采集目录重试时，只有原视频完整摘要和全部桌面缓存摘要都一致才复用压缩结果及倍速、预览图，继续续传，不重新编码；索引不包含凭据，不把另一份长期媒体缓存放回项目目录。

**导入平台、登记采集目录和分配任务只建立记录。** 新上传的最终清单包含服务端核验获得的媒体元数据；导入据此建立项目时长、录制时间、断档和素材指纹，不下载视频、不创建占位视频文件，也不运行 FFmpeg。已有项目保留原有坐标、草稿和名称。历史完整缓存清单缺少媒体元数据时，优先读取已有项目记录或服务器现存的核验信息；两者都缺失时明确拒绝并提示补齐元数据，登记不会为此重新下载视频。更早没有完整上传缓存的历史清单继续使用原兼容流程。

进入标注或复核时，服务端直接提供已发布缓存清单与授权链接。浏览器最多三路下载、两路完整校验，最多六个文件在处理中；下载完成即可释放网络名额，不必等待该文件校验结束。新文件写入前批量保存引用登记，完成后确认就绪；有效缓存复用且登记与版本清单未变化时不重写元数据。登记写入仍串行协调，任一文件失败不能报告就绪，已完成文件保留供重试；取消后等待所有请求收尾。普通视频、倍速视频与图片仍须完整下载并通过大小和摘要检查后才可进入标注；同机换账号继续复用符合清单的已有媒体文件。

S3 状态查询与就绪确认仍校验缓存清单的完整关联，但不生成下载签名；仅请求素材清单时生成签名。任务工作区在一次请求内复用已授权的解析结果，同一来源项目只读取一次，每段视频仍检查素材和录制坐标；不跨请求缓存权限或草稿。准备页同时显示已就绪容量、下载量、完整校验量、当前并发数与耗时，进度条按已校验就绪字节计算，下载和校验可同时进行。

采集日期取所选 AVI 文件名中的最早录制日期，人物目录为“月日＋填写的采集人”；例如 2026-10-10 的 `lixin` 写入 `daily/20261010/1010lixin/`。选择整个采集根目录时，按以下内容处理：

| 目录 | 内容与处理 |
| --- | --- |
| `FPV/` | 从根目录、`video/` 或 `FPV/` 的 AVI 生成现有 480×270、H.264 256 kbps／AAC 32 kbps 压缩视频；普通压缩缓存同时保留在上传者桌面 `dataMarkProject/1010lixin/`。 |
| `IMU/` | 原样上传所选根目录下 IMU 的数据文件，保留子目录。 |
| `HEART/` | 原样上传所选根目录下 HEART 的心率文件，保留子目录。 |
| `prediction/` | 原样保留合法 UTF-8 JSON 的字节；符合下文版本和素材校验的 posture.json 可用于首次空白草稿初始化。 |
| `timeline/` | 由平台正式标注输出生成，包含人工修改后的 `posture.timeline.json` 及其他选中轴；继续使用下述版本目录和指针。上传不会读取或覆盖本机已有 timeline。 |

IMU／HEART 支持 `.csv/.tsv/.txt/.json/.bin/.dat/.npy/.npz/.parquet`，IMU 另支持原样上传 `.wplay`（含数字子目录内的文件），prediction 只接受 JSON 对象或数组，单文件上限 32 MiB。可上传 1–1000 个 AVI、最多 4000 个附属文件，单文件上限 16 GiB、采集总量上限 100 GiB。目录名匹配不区分大小写，拒绝符号链接、Windows 目录联接、路径越界、重复目标名以及已发生变化的源文件。根目录身份 TXT、隐藏文件、已有缓存及 timeline 等排除项在确认清单中明确列出；受支持数据目录内出现不支持的格式时拒绝并提示，不静默发布缺失数据的目录。只选 `video/` 时不会隐式读取其父目录中的 IMU／HEART，需要附属数据时选择整个采集根目录。

压缩视频和附属文件都使用“内容摘要＋原文件名”的不可变对象名，逻辑文件名及 SHA-256 保存在同一 `manifest.json` 中，避免相同目标目录的并发上传覆盖内容。视频编码／时长与所有文件的大小／摘要验证成功后才发布采集清单；prediction 和 IMU／HEART 不进入视频列表。目标采集目录已存在时拒绝覆盖，已有 timeline 保留。本机助手要求公网健康接口声明 `s3-folder-upload`，后端未升级时明确拒绝开始，不能只更新前端或本机工具后就报告公网上传可用。

对象层级为 `daily/<采集日期>/<月日+采集人>/`，压缩视频放在 `FPV/<内容摘要>-<原视频名>.mp4`，`manifest.json` 是完整发布的目录清单。标注员登录公网后选择已发布目录，沿用相同的时间轴与权限操作，准备阶段从 R2 下载并校验普通、倍速视频和预览图，保存到授权的桌面 `dataMarkProject/<采集目录名>/`。上传者重开同一目录时复用内容相同的普通视频缓存。网页直接保存指定桌面目录仍要求 Chrome／Edge 支持并授权目录读写，Safari 不具备这项接口；填写路径不能代替浏览器授权。

草稿保存在 Ubuntu 的独立公网项目库。正式 JSON 保持现有格式，写入 R2 的 `timeline/versions/<保存编号>/<轴名>.timeline.json`；`timeline/.latest.json` 一次条件更新指向本次完整版本，并读回核验。重新打开时只读取该指针中的完整批次；未选择的轴保留原版本，已删除的自定义轴不再出现在最新指针中，旧版本保留。遇到他人已更新的对象或草稿版本时拒绝覆盖并保留本页草稿。此版本目录不等同于 NAS 的根目录文件布局，也不会自动同步到 NAS。

现有 Windows 草稿数据库记录了 Windows 原视频绝对路径，不能直接复制到 Ubuntu 使用。**所有用户先保存浏览器中的未提交编辑，停止旧平台并禁止继续编辑**，再在旧机器项目目录运行 `.venv\Scripts\python.exe -m deploy.migrate_projects export --state .local --output <仓库外的安全迁移包目录>`；脚本通过 SQLite 快照备份标注库及已有账号库，并逐个读取原视频计算完整 SHA-256。将整个迁移包经批准的内网传输方式送到 Ubuntu，限制目录权限为仅部署账号可读。按实际 NAS 挂载修改 `deploy/intranet-paths.example.json` 并另存为被 Git 忽略的 `deploy/intranet-paths.json`，补齐其它原视频路径映射。保持 Ubuntu `state/` 不存在，运行 `python3 -m deploy.migrate_projects apply --bundle <迁移包目录> --state <DATAMARK_HOME>/state --mappings deploy/intranet-paths.json`。迁移会逐段比对完整 SHA-256、核对原 `timeline/` 文件，保留项目 ID、已保存草稿、编辑历史、已有账号与分配并使旧登录失效；任一文件不一致就不创建目标状态目录。若旧平台没有账号库，迁移输出会明确提示，随后使用上文交互命令创建首位管理员。迁移不复制可再生成的本机播放缓存，Ubuntu 首次打开项目时需要重新准备或复用 NAS 缓存。迁移完成并创建管理员后再运行上面的 `up -d`，逐项目验收。迁移包含账号和个人数据，确认 Ubuntu 验收和备份后按公司规则保管或清理。本机服务在 Windows 和 macOS 均可点选视频文件或原视频目录；Ubuntu 服务仅以完整 NAS 采集目录作为新项目领取单位，支持目录浏览或填写 NAS 完整路径。访问者电脑上的本地文件不会自动出现在 Ubuntu 服务器上，需要通过本机服务同步进度和最终 JSON。

本机测试已挂载的 NAS 时，macOS 可在启动进程设置 `DATAMARK_LOCAL_NAS_ROOT=/Volumes/homes/datacollection`，再运行 `.venv/bin/python launch.py --no-browser`。Windows 使用标准共享目录 `\\Relty\homes\datacollection` 时，现有 **启动标注平台.lnk** 会自动按该目录只读查找缓存；打开该共享目录中的原视频或采集目录即可。若 Windows 使用映射盘或其他共享路径，在同一个 PowerShell 窗口运行 `$env:DATAMARK_LOCAL_NAS_ROOT='X:\datacollection'; .\.venv\Scripts\python.exe .\launch.py`，将路径改为实际挂载的采集根目录；这不修改系统环境变量。本机项目使用独立账号和项目 ID，草稿仍保存在本项目的 `.local/`，精简播放缓存写入桌面 `dataMarkProject/<采集目录名>/`；不会认领或改写 NAS 上现有的 `.datamark-cache` 所有权标记。

若 NAS 上有内网服务完整且校验通过的 `.datamark-cache/ubuntu-playback-v1/<项目ID>/` 精简播放缓存，本机会复制普通与倍速视频及图片到桌面采集缓存目录，校验后供浏览器下载；已配置 Windows NAS 处理服务时也先复用有效的挂载缓存，缺失或损坏时继续原有准备流程。旧缓存若由不同的 Ubuntu 路径生成，可用 `DATAMARK_LOCAL_NAS_SERVER_ROOT` 指定其采集根目录，默认 `/mnt/nas/homes/datacollection`。此设置只影响本机读缓存；NAS 写回仍按项目原有的目录与权限规则执行。更新代码后须先退出正在运行的旧本机服务，再启动快捷方式；启动器会复用仍在运行的旧进程。

## 桌面的播放缓存目录

本机启动和网页下载均使用以下媒体目录。缓存根目录默认为系统桌面的 `dataMarkProject`，下一级直接使用原采集目录名，例如 `1010zengl`，不再拆分日期与设备编号，也不随项目显示名称的修改而移动。

```text
桌面/dataMarkProject/1010zengl/
  <视频名>.<内容版本>.normal.mp4
  <视频名>.<内容版本>.fast.mp4
  <视频名>.<内容版本>.thumbnail.jpg
  <视频名>.<内容版本>.storyboard-001.jpg
  manifest.<素材批次版本>.json
```

NAS、S3、本机生成的缓存采用相同的本机目录和文件规则，保留普通视频、倍速视频、封面及全部悬停预览图；不下载或复制原视频。服务器生成后存到 NAS 或 S3 的缓存继续作为下载来源。项目数据库、标注草稿与账号信息仍由现有应用管理，不放进这个媒体缓存目录。NAS 和模拟模式保持原规则；真实 R2 使用下文的独立公网配置，必须单独部署和验收。

内网 Ubuntu 的 NAS 精简播放缓存按素材与压缩配置共用，新增缓存放在原视频目录的 `.datamark-cache/ubuntu-playback-v1/<素材缓存键>/`。不同账号、任务或项目再次打开同一素材时，校验原视频身份和缓存完整 SHA-256 后直接复用；已生成的旧项目缓存也在原处读取，不搬移、覆盖或删除。当前单进程内网服务对同一素材的并发准备排队，避免重复压缩；等待者可独立取消。原视频或压缩配置变化时使用另一缓存键。共用的仅是播放文件，账号权限、任务草稿、标注和提交仍各自隔离；本机清理不删除 NAS 缓存。此规则不作用于公网 S3/R2 或模拟 S3，公网继续复用上传者生成的缓存。

上传者也使用这套目录：通过本机上传流程生成的普通压缩视频，在发布前按内容摘要保留到 `dataMarkProject/<采集目录名>/`，上传临时目录清理后仍保留。打开同一已上传采集目录进行标注时，校验并复用上传时保留的普通视频、倍速视频和预览图，仅补齐缺失或失效文件；不会另存一份永久的普通视频。发布失败也保留已生成且校验通过的桌面缓存，原 AVI 不修改。上传缓存独立保留，不随其他标注项目的预览清理删除。缓存位置与正式 JSON 的写回目标是两回事：NAS 项目仍写回对应采集目录的 `timeline/`，S3 模拟项目当前写回模拟对象目录的 `timeline/`；真实 R2 项目写回 R2 的版本目录，不自动写回 NAS。

采集目录名应在导入时作为独立元数据确定并保持稳定，不使用可能被重命名的项目名称。目录导入使用原采集根目录名，选择 FPV 时使用其父目录名；单文件导入优先使用文件父目录，多目录素材无法确定时暂用素材指纹命名，可在“缓存位置”中填写采集目录名。项目改名不改变缓存目录，不猜测设备编号。同名目录对应不同素材批次时仍可分组到同一目录，但文件名与清单必须包含内容版本以避免覆盖；路径片段须兼容 Windows 和 macOS，并禁止路径穿越。媒体文件名绑定输出内容 SHA-256 和素材名称，清单记录预览生成配置；文件复用核对大小与完整 SHA-256，不依赖临时下载链接。浏览器对不超过 64 MiB 的文件使用原生加密接口计算摘要，较大文件在浏览器后台线程中使用有界内存流式计算，取消时终止线程；不支持后台线程的环境仍沿用流式完整校验，不跳过检查。这样相同素材及相同预览版本才可跨运行方式复用。

Windows 和 macOS 通过 `launch.py` 启动时，由本机服务定位系统桌面并创建目录，Windows 应识别 OneDrive 等重定向桌面，不硬编码旧用户名路径；顶部与素材准备页均提供“缓存位置”：本机模式可修改缓存根目录，所有模式可设置当前项目的采集目录名。设置保存在项目的 `.local/` 中，不修改系统环境变量。网页模式在首次准备前由用户点击选择并授权桌面的 `dataMarkProject`，通过支持目录读写的浏览器直接保存和读取文件；每个网站分别记住目录句柄，并在重新使用时核验权限，权限失效时提示重新授权。网页无法未经授权直接创建任意桌面路径。不支持目录读写的浏览器需使用本机服务完成该保存流程，不能悄悄退回浏览器专用缓存后声称已保存到桌面。相关浏览器限制见 [Chrome 文件系统访问说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

下载前检查对应版本的清单、文件大小与 SHA-256，仅补下载缺失或损坏文件。媒体流直接写入目标文件，检查文件大小与 SHA-256 后才将该项记录为可用，全部必需素材就绪后进入标注；中断任务保留已经校验的文件，未完成文件不能参与播放。清单记录稳定的素材身份、预览规格、相对文件名、大小及摘要，不保存凭据或临时签名链接；同目录同时下载时使用不可变内容文件名与独立项目引用，浏览器同网站内串行协调写入，原生服务按写入锁发布；批次清单分别保存。损坏的已登记文件先保留恢复副本再修复，未经登记的同名文件不会覆盖。打开项目仍须通过当前服务的账号和项目权限校验。

播放、封面和悬停预览统一读取这份桌面缓存，新流程不再额外保存第二套完整浏览器媒体副本。已有项目内部缓存或浏览器缓存先经校验迁移到新目录，再切换读取；旧缓存不立即自动删除。项目下拉内的移除操作只清理本应用登记且没有被其它项目引用的缓存文件，并按账号记住本机列表隐藏状态，不清空整个采集目录，不删除用户自行放入的文件、项目记录、草稿、NAS/S3 缓存或正式 JSON。本次实现的回归测试覆盖缓存落盘、旧缓存迁移、文件校验、共享引用保护以及 Windows 已知目录查询；实际浏览器授权、macOS/Windows 启动和真实素材仍需用户验收。后续验收须覆盖两种系统、实际重定向桌面、NAS/S3 来源、网页授权与重开复用、同名素材冲突、中断后继续准备、磁盘不足以及安全清理。

本机以 `DATAMARK_STORAGE_BACKEND=nas` 运行 NAS 浏览和领取界面时，还须显式将 `DATAMARK_LOCAL_NAS_ROOT` 设为本机挂载的采集根目录（Windows 标准共享为 `\\Relty\homes\datacollection`）。此组合沿用 NAS 目录和账号权限检查，但将视频缓存作为只读的内网服务缓存：跨项目 ID 查找并校验已有 Ubuntu 缓存，下载到本机 `.local/`，不创建或改写 NAS 缓存所有权标记，也不向 Ubuntu 缓存目录发布本机预览。缓存不可用时继续本机准备。Ubuntu 正式 NAS 服务不设置此本机选项，保留原缓存发布流程。该设置仅限制缓存写入，正式 `timeline/` 标注写回仍按既有权限执行。

## Windows 本机模式的服务器准备 NAS 素材

NAS 素材可以由 `relty-server` 读取、生成播放缓存并打包，再下载到本机。服务器通过有线网络读取 `/mnt/nas/`；电脑继续使用 Wi-Fi，无需接网线。原视频不上传到服务器，也不下载到本机。本机启动后，标注页面读取桌面 `dataMarkProject/<采集目录名>/` 中的普通预览、倍速视频、封面和悬停图，本机草稿及现行标注流程不变。

服务器使用有线地址 `192.168.2.25`，部署目录为 `/home/relty/services/datamark-worker/`。服务仅监听服务器的 `127.0.0.1:18120`，本机通过专用 SSH 密钥建立 `127.0.0.1:18121` 隧道；浏览器访问的本机应用仍是 `http://127.0.0.1:8765`。无需在局域网开放工作服务的 HTTP 端口。服务器的 `state/` 用于处理中间文件和任务记录；完成的缓存包持久保存到原视频目录的 `.datamark-cache/remote-v1/`，例如 `FPV/.datamark-cache/remote-v1/`，不修改原视频。

首次部署在本项目根目录的交互 PowerShell 中运行：

```powershell
.\deploy\deploy.ps1
```

部署脚本使用项目内 Python 执行 `deploy/deploy_worker.py`，提示准备好后再进行 SSH 登录；密码仅在 SSH 终端中输入。它安装项目专用 SSH 密钥、配置服务器运行环境和服务，并将本机连接配置保存到 `.local/remote/worker.json`。密钥、令牌和已信任主机记录也保存在项目的 `.local/remote/` 内，不提交到 Git。首次部署完成后，平台自动建立隧道、提交准备任务和下载缓存，无需每次输入密码；关闭平台后本机隧道停止，服务器已接受的处理任务可以继续。

`worker.json` 包含 `enabled`、`host`、`user`、`port`、`local_port`、`identity_file`、`known_hosts_file`、`host_key_alias`、`token_file` 和 `mappings`。文件路径为本机绝对路径；令牌从 `token_file` 指向的文件读取，不写入源码。当前服务器有线地址使用已验证的同一主机记录，`host_key_alias` 为 `192.168.2.126`。默认共享目录映射如下，实际导入路径应匹配配置中的 `local` 前缀：

| 本机共享目录 | 服务器目录 |
|---|---|
| `\\Relty\datasets` | `/mnt/nas/datasets` |
| `\\Relty\collector-data` | `/mnt/nas/collector-data` |
| `\\Relty\homes` | `/mnt/nas/homes` |
| `\\Relty\docker` | `/mnt/nas/docker` |

准备遵循三级顺序：先复用完整有效的本机缓存；本机缺失时由服务器检查原视频旁的 NAS 缓存包；NAS 也无有效缓存才生成与原流程兼容的精简视频、快进视频、缩略图和悬停图集。缓存身份包含原片指纹、时长和预览规格，包与元数据分别保存为内容 ID 对应的 ZIP 和 JSON。写入使用独立临时文件、校验和及原子替换；NAS 保存和校验成功后才提供下载，并清理该任务的服务器中间视频、散文件和本地 ZIP。NAS 写入失败时保留服务器已完成的包，重试优先补保存，不重新转码。旧版服务器已有的有效 ZIP 会在对应素材再次请求时迁移到 NAS。

本机从服务器下载 NAS 中的缓存包，校验后安装到原播放缓存目录，成功后删除本机下载临时包；播放时仍只读取本机文件。页面区分“检查 NAS 缓存”“服务器处理中”和“下载到本机”，命中 NAS 时无需重新生成。未映射的本机视频继续使用本机准备流程。选择和列出共享目录时仍可能通过 SMB 读取少量目录元数据。已完整保存在本机的旧缓存不会仅为补存 NAS 而重新上传或转码。

内网网页容器的 CPU 配额由持久部署配置 `DATAMARK_WEB_CPUS` 控制，默认 4 核；10443 开发版采用 6 核，并通过 `DATAMARK_PREPARATION_PARALLELISM=3` 同时准备最多三段视频，内存限制仍为 6 GiB。并行数量支持 1–4，未设置或值无效时默认 2；重复素材仍串行处理。该配置只控制内网网页容器，不改变独立远程压缩容器的配额。此前两段并行时，实测同一批四段真实视频各取前 60 秒、完整生成预览，两轮平均耗时由 4 核的 20.46 秒降为 6 核的 9.06 秒；此结果仅代表该样本的预览生成阶段，不代表整个新建项目耗时。

服务器双任务配置为 `DATAMARK_WORKER_SLOTS=2`、`DATAMARK_FFMPEG_ENCODER_THREADS=2`，两个任务各有独立准备上下文，同一素材请求去重；容器仍限制为 4 CPU、6 GiB 内存。若实测双任务收益不足，可回退为单任务、4 编码线程，不改变缓存格式。没有开启核显加速或新增系统驱动。任务日志记录排队、NAS 检查、各转码阶段、打包、NAS 保存和清理耗时；本机记录等待、下载校验及安装耗时。缓存包直接存储已压缩的视频和图片，避免重复压缩。下载进度约每 250 毫秒更新，取消和断点续传仍按收到的数据块及时处理。

远程请求或缓存包下载遇到可恢复的连接故障时，平台会自动重连，等待间隔依次为 1、2、4、8、15、30 秒，之后保持 30 秒；每次重连最多自动尝试 5 分钟。准备页面显示“重新连接服务器”和下次重试的等待时间，保留当前进度及已完成的缓存；连接恢复后继续准备，缓存包通过 HTTP Range 从已有下载位置续传。超过重试时限仍未恢复时，页面显示错误并提供手动重试。认证、权限、素材冲突、数据校验或磁盘空间不足等错误直接提示，不进入自动重连。NAS 素材不会因重连失败而改为本机转码。

单个片段的素材或校验失败会保留该项错误，其余片段继续准备，页面持续更新已就绪和失败数量。整批结束后可以重试失败项，也可以选择“跳过失败片段并标注”，查看文件清单并勾选确认后进入标注。至少须有一段可用视频，且其余任务全部结束；未准备完成的片段不能直接进入播放。跳过只改变本项目的标注范围，不删除原片、NAS 缓存或本机已完成缓存，不移动任何视频的时间坐标；时间轴对应区间留空，导出的 timebase.skipped_videos 记录文件名、区间和失败原因，覆盖校验仅针对未跳过的录制范围。选择会保存在本机项目中，并可从准备页“恢复已跳过片段”。已有标注与新增空档冲突时禁止跳过，保留草稿。用户主动取消、切换项目或关闭平台时仍会停止当前本机准备任务。

下载完成的项目可以在断开 NAS 和转码工作服务器后继续播放、标注和保存本机草稿；新的 NAS 素材准备、缺失缓存修复及云端输出需要相应服务可用。内网网页服务生成 NAS 项目的精简预览后，先将普通视频、倍速视频和图片写入原 FPV 旁的 `.datamark-cache/ubuntu-playback-v1/<项目ID>/` 并读回核验，再通过授权接口完整下载到标注电脑的本机存储。浏览器确认下载完成后，Ubuntu 才清理临时播放副本。项目下拉中的移除按钮会清理当前浏览器及服务端临时预览，并按账号在当前浏览器隐藏项目，保留 NAS 缓存、平台草稿和原视频；通过新建重选原素材后复用 NAS 缓存，无需重转码。“导出 JSON 到云端”将本次勾选轴的文件写入 NAS 采集目录的 `timeline/`，跳过习惯轴，检查外部修改冲突并保留 `.annotation-backups` 备份；实际读回成功后才显示完成。本地独立 JSON 导出不要求 NAS 或转码工作服务可用，网页仍需连接当前平台接口。

此流程减少本机重计算和无线传输的原始数据量；实际准备时间取决于服务器负载、NAS 读取速度、素材时长和缓存包大小，不预设加速倍数。服务器生成的预览规格和本机播放路径不变，播放阶段不增加服务器往返请求。

## 操作流程

素材播放就绪后，视频预览按可用宽度和视频自身比例调整尺寸，画面高度不超过窗口高度的 70%，最高 640 像素，完整显示画面，不裁切或拉伸。预览外框随画面比例调整，不再为了填满整列而过度放大。窗口高度不足时可上下滚动工作台查看播放按钮和下方时间轴；右侧操作面板保持独立滚动。普通滚轮用于上下浏览，原有进度及时间轴缩放快捷键不变。此布局适用于 Chrome 和 Edge。

1. 点击“新建项目”，可先填写项目名称。Windows 或 macOS 本机服务可通过系统选择窗口多选视频或选择原视频目录，也可填写本机可访问的完整路径。Ubuntu 服务可在网页中逐级浏览 NAS，选择完整采集目录，或填写服务器可访问的完整 NAS 目录路径。新 NAS 项目按目录领取，避免同一文件进入两人的草稿。若目录已被其他账号认领，页面显示原认领人并要求两次确认后才转交项目权限；旧账号随即不能再访问该项目。若目录已有时间轴 JSON，领取时须选择沿用它继续标注，或先将旧 JSON 备份到 NAS 的 `.annotation-backups/claim-<编号>/` 后从空白开始；原 JSON 在首次写回前仍保留。已有平台草稿在切换标注来源前保存于 `.local/projects/<项目ID>/recoveries/`。服务端会在最终领取前重新核对认领人、项目版本和 NAS 文件，变化时须重新确认。本机项目可选择文件夹导出独立 JSON；选择目录导入时，“导出 JSON 到云端”沿用原“写回原目录”功能，保存到该目录的 `timeline/`。单独选择视频可预览和导出独立 JSON；未关联统一原采集目录时不能写回原目录。所有 NAS 方式均由 Ubuntu 直接读取原视频，不复制到平台。
2. 从文件名读取视频拍摄开始时间，支持 `设备编号_YYYYMMDDHHMMSS_片段序号.扩展名`，例如 `A09999_20260911131330_0000.avi` 表示 2026-09-11 13:13:30，`A09999_20260911131332_0001.avi` 表示同日 13:13:32。中间 14 位决定现实起点，末尾 `0000` / `0001` 是序号，不作为毫秒；第二段位于全局时间轴第 2 秒，是否有空档由第一段实际时长决定。保留视频原有的 `.avi` / `.mp4` 等扩展名（不区分大小写）。按真实拍摄时间排序，以最早视频开头作为时间轴零点，保留中间没有录制的空档；播放会跳过空档继续下一段。每段保留独立原始文件，不生成合并视频。视频始终保留原位置，平台只记录引用路径。
3. 左上预览视频，点击倍速分段按钮，即时切换 `0.5、1、2、5、10、50、100` 倍速，高亮滑块指示当前档位。在下方视频轴或标注轴空白处定位，也可按住蓝色光标或轴面拖动；所有手动调整视频进度的操作都会先暂停，拖动松开后也保持暂停；需要继续时按空格或点击播放。鼠标悬停在视频轴、刻度尺或任意标注轴时，显示贯穿各轴的竖线及预先生成的图片、时间轴时间与现实时间；靠近视频分界、标注起止点或锚点时自动吸附，点击后播放头定位到该时间。悬停本身不改变播放位置；图片每秒采样并注明预览帧时间，真实断档注明无视频。点击轴名或右侧类型选项切换标注面板；点击已有色块则选择该标注并定位。50 / 100 倍采用预生成的 640×360 快进视频连续播放，避免反复跳转解码；暂停或切回低倍速时恢复本机普通预览，并定位到相同的时间轴时点。快进预览无音频，抽帧仅用于快速浏览，JSON 仍使用原时间轴；录制间隔自动跳过。
4. 默认显示场景、姿势、大类三条时间轴，各轴均允许留空和多状态重叠。**场景：**室内、室外、半开放、隧道、电梯、交通工具内、Unknown。**姿势：**坐、站、躺、移动、骑行、交通工具坐、交通工具站、交通工具躺、Unknown。**大类：**工作学习、运动锻炼、饮食、出行、社交、休闲娱乐、休息、日常事务、Unknown。尚无状态标注时，首次选择标签铺满全部已录制的连续范围（`recording_runs`），真实断档留空；之后在变化时间点击标签切换主轴状态，保留后续已设定的主轴状态边界和全部子轴标注。旧项目标签和标注原样保留，不自动更名。
5. **大类：**普通点击标签完成主轴状态标注；选择锚点区间后点击标签，从主轴向下逐层填入空白、合并相同内容，只有冲突部分继续放入下一层子轴。各轴允许全部或部分留空，旧版 overlay 区间继续读取与显示。
6. **自定义轴：**所有新标注均为持续区间，不再提供瞬时事件类型或发生时点入口。已有事件轴可先填写标注内容，也可先标记开始和结束；快捷标签可填入内容，新增时保留自由输入，补齐后点击“保存标注”。锚点选区内的标注按既有逐层规则归并，跨录制空档时拆成有视频的片段。内置习惯轴已停用，不再提供时间轴库、选择或录入入口；历史标注和已有 JSON 保留。
7. **锚点选区：**将播放头定位后点击“添加锚点”（也可按 Ctrl + 空格），在该时间显示无编号锚点；当前位置已有锚点时，同一操作会删除该锚点。最多保留两个，继续添加会移除最早添加的一个。保留一个“选中区间”按钮，显示两个锚点的间隔；不足两点时显示 `--:--:--` 并禁用。添加锚点不自动进入选区，点击按钮后才按两点时间先后选中区间。工具栏另行显示当前播放头到最近锚点的间隔，时长均采用时:分:秒格式。选区内一次标注一个状态，无需勾选子轴：保存时从主轴开始，按子轴编号由小到大逐层检查。空白部分写入本层，完整标签（含备注）和模式相同的持续区间部分合并，只有与不同内容或历史零时长记录冲突的部分继续向下一层查找；已有内容保留。例如主轴 0–10 秒站、10–15 秒坐，锚点标注 0–15 秒站后，子轴只新增 10–15 秒站。主轴已占用、子轴已有 16–21 秒饮食时，新增 20–23 秒饮食会将该子轴扩展为 16–23 秒，不再新增一层。各片段可分配到不同层，尽量复用靠上的轴；已覆盖的相同内容重复保存不会增加记录，确有冲突才增加子轴，数量不设上限。真实断档不填。完成一次区间标注后自动退出选区并清空本次输入，保留锚点和间隔，可再次点击“选中区间”复用。场景、姿势、大类点击标签即完成，自定义事件点击保存后完成；输入校验失败保留选区。取消选区及点击刻度尺、视频轴或标注轴会退出选区并保留锚点；工具按钮、悬停和滚轮浏览不退出选区。清空按钮一次删除全部锚点和选区。锚点和选区不写入标注 JSON。
8. 点击任意标注色块选中该段，在独立的“编辑标注”模块修改内容。标签统一使用下拉选项，选中后立即替换当前色块；备注输入后按 Enter 或离开输入框自动保存，可留空，不再显示起止时间输入和“保存标注”按钮。内容编辑保留原起止时间及主轴／子轴位置，连续相同内容仍按现行规则合并。点击删除按钮或按 Delete 删除已有整条色块，所有轴删除后均保留空白，不顺延前段或自动补齐。输入框中 Delete 正常删字。Ctrl + Z 撤销修改或删除，Ctrl + Shift + Z 恢复；撤销后有新修改会清空恢复记录，底部不再提供两项按钮。
9. 改动自动保存到本机草稿，草稿允许未标注空白。确认状态栏显示“已保存到平台”；有保存错误时点击“重试保存”。项目下拉可继续已保存工作。旧项目新增的大类默认为空，不推断或改写现有标签。
10. 在“标注输出”中选择 **导出 JSON 到本地**，授权保存文件夹后逐轴写入独立 JSON，并逐个读回核验，不生成 ZIP；需要支持目录读写的 Chrome 或 Edge，以及 HTTPS 或 localhost 页面。**导出 JSON 到云端** 是原 **写回原目录** 按钮的新名称，目标和保存流程不变，仅写当前勾选轴：NAS 项目写回原采集目录的 `timeline/`，本机目录项目先写回本机原采集目录的 `timeline/`，S3 模拟项目沿用模拟对象目录的 `timeline/`。本机已连接云端账号时，在本机写回成功后，沿用已有账号同步机制同步经核验的最终文件，由 Ubuntu 写入对应 NAS 目录并读回核验；未连接或同步失败时保留本机写回结果并提示，不能报告 NAS 保存成功。已有 `timeline/` 时始终以其中的标注为准，即使文件被全部删除也不会重新读取根目录旧批次；只有没有 `timeline/` 时才兼容根目录旧文件。新输出不删除根目录旧文件。若平台还有未写回的草稿，重新选择目录会保留草稿并提示外部文件变化。确认 NAS 时间轴 JSON 已全部删除后，可点击 **清空旧标注并重来**；服务先在 `.local/projects/<项目ID>/recoveries/` 保存私有恢复副本，再清空草稿并更新外部文件基准。NAS 仍有时间轴 JSON 或项目版本已变化时拒绝清空。草稿和正式输出均允许轴全部或部分留空；本地输出包含三个固定轴及项目已有自定义轴，包括未勾选轴，云端只输出当前勾选轴，两者均跳过已停用的习惯轴且不删除其已有 JSON。本地输出前须结束所有输出轴的事件区间，云端只检查勾选轴；全部未勾选时禁止云端输出。输出弹窗不清理缓存，清理并移除本机项目使用项目下拉内对应项目的垃圾桶按钮。

**调整标注边界：**先单击选中标注，再单独点击该色块的左边缘或右边缘，边缘显示简洁高亮手柄，大视频定位到对应边界。无需快速双击；第一次点击边缘只选择整段，已选中后第二次按下边缘即可拖动。选中边界后，鼠标靠近金色边界竖线时显示左右拖动光标；只有拖动边界，以及左右方向键及其 Shift / Ctrl 组合、Home / End、Shift + 滚轮和 Ctrl + Alt + 滚轮等进度快捷键可以调整该边界，大视频同步预览对应时间，调整后保持暂停。所有轴的主轴和子轴均支持。

边界调整只影响同一条主轴或同一条子轴：与相邻标注首尾相接时，两侧边界一起移动，始终相连；向相邻标注内部扩展时可将其完全覆盖，并继续覆盖后面的标注，被覆盖的标注会删除。选中段自身至少保留 1 毫秒，不能越过自己的另一端，也不能跨过无视频的真实断档；其他轴和其他子轴保留原样。按 Esc 退出边界选中。边界选中时，点击时间轴其他位置（包括刻度、视频、空白和其他色块）只取消边界选中，本次点击不移动播放头或边界，也不改选其他色块；退出后再次点击恢复普通定位和选择。“标注面板”“编辑标注”模块内的操作保留边界选中，点击其他区域或开始播放退出。修改自动保存，一次拖动、连续按住方向键或连续滚轮调整分别作为一次操作撤销，撤销会一起恢复联动及被覆盖的标注。

右上角“时间轴库”弹窗统一创建、修改、删除时间轴，并编辑名称和标签。创建、修改在同一弹窗内切换页面，保存或取消后返回列表；删除另开确认弹窗，取消或 Esc 仅关闭确认窗。创建和修改不再显示类型选项，新轴默认使用状态标签，已有轴保留原类型。每个账号具有自己的个人库，初始共享以上三条默认轴；普通账号只能查看默认/个人分类和维护自己的个人轴，不能修改默认身份或编辑、删除默认轴。管理员可在每条轴旁点击“增加为默认时间轴”或“移除默认时间轴”：增加后所有账号共享，移除后转入操作管理员的个人库并保留定义，可再次增加为默认；新轴先进入个人库。JSON 名与其他账号个人轴冲突或目标库达到容量上限时拒绝切换，不覆盖现有定义。库变更不会同步到已使用该轴的项目。旧版账号模板保留为个人库条目。每条轴的 JSON 名创建后不变。点击已有色块可编辑该段备注，例如“室内（餐厅）”，备注只影响当前标注。

补导入视频的页面入口与新增补导入 API 已移除。新建时一次选择需要的完整素材；历史上通过补导入形成的组合项目仍可正常重开，原视频引用、标注和时间坐标保留。时间轴对照入口和功能也已移除。

无视频的真实断档在时间轴上压缩为窄断档，悬停显示实际起止时间；压缩仅影响显示，播放、锚点、标注和导出 JSON 均保留真实时间。时间轴默认每屏显示约 1 小时，短项目显示全程。鼠标放在时间轴内，按住 `Ctrl` 向上滚轮放大、向下缩小，以鼠标所在时间为中心；最细每屏 1 分钟，最宽显示整个项目。缩放不改变播放位置、锚点或选区；工作台内的 `Ctrl + 滚轮` 不再缩放浏览器页面。普通滚轮上下滚动页面或时间轴中的重叠层，`Alt + 滚轮` 左右浏览时间；触控板横向手势及底部横向滚动条也可左右浏览。时间轴工具栏右侧提供 1 分钟时长参考带，由 60 个 1 秒格组成，从右向左累计，每 5 秒显示较高分隔线，30 秒与 60 秒加粗，两个半分钟区间用深浅底色区分；文字优先保留 5s、30s、60s，空间充足时补齐每 5 秒标签并避免重叠；长度随缩放及窗口宽度同步变化，与有视频区间比例一致；靠右向左延伸，空间不足时裁切左侧，不显示“每格 1 秒”和“部分显示”字样，不压缩比例或覆盖现有按钮，跨真实断档不适用。视频右下角不显示时钟。顶部刻度、标注色块提示和锚点选区显示统一使用标注 JSON 的录制起点加毫秒偏移，显示视频真实时间（北京时间），悬停刻度可查看完整日期；录制起点缺失时明确显示相对时间。时间轴右上角的左右浏览、回到光标、1小时和录制时长组件已移除，标注面板不再显示当前时间卡片。

当前项目启用的场景、姿势、大类预置轴与自定义轴同时显示，时间刻度与视频轴固定上方。每条主轴下方缩进显示“子轴 1、子轴 2…”及连接线，不限制层数；普通滚轮在时间轴区域整体上下查看，选中色块时自动露出其所在子轴。右侧分为“项目管理”“标注输出”“标注面板”“编辑标注”四个模块。项目管理收起时为项目下拉和本机播放就绪状态两行；展开下拉后最上方是虚线圆角框“新建项目”，每个项目后提供改名和移除按钮。标注输出集中提供云端导出、本地导出和姿势 JSON 导入。未选择项目时，预览区引导选择素材，场景、姿势、大类三条默认轴作为示例可见；素材就绪后才显示标注内容。标注记录通过时间轴色块查看和编辑，编辑历史入口在标注面板标题旁。保存状态保留在顶部，异常时提供重试与恢复副本入口。

新建导入和手动切换项目时，会进入素材准备页面。刷新恢复最近项目时先读取已有准备状态；素材已就绪则载入预览图片并直接进入工作台，不重复发起准备或要求再次点击“开始标注”；缓存缺失或失效时才继续准备并显示进度。移除本机项目后不自动恢复该项目，重新打开页面停留在素材选择界面；通过“新建项目”重新选择原素材可恢复原项目，并按需准备。准备只处理缺失或失效的素材。配置了服务器映射的 NAS 素材由服务器准备并下载，本机素材直接生成精简视频、倍速视频、封面与悬停图。关闭准备页面会返回项目选择界面，不进入未准备好的标注页。首次准备耗时较长，之后复用已完成缓存。

原视频始终在原目录。旧版在原目录 `.datamark-cache/<项目ID>/preview/` 生成的完整预览继续保留，本机准备流程可复用；新的标注准备直接生成精简预览，不再先生成这份大型中间视频。精简普通预览为 480×270、保留原帧时序，视频目标码率约 256 kbps、音频约 32 kbps，另有倍速预览和缩略图。本机模式在桌面的 `dataMarkProject/<采集目录名>/` 保留这套缓存；Ubuntu 内网服务在同一位置临时生成，写入并校验 NAS 缓存后，等待浏览器下载完成再删除临时副本。此画面适合快速浏览和标注，清晰度低于原片；原视频、标注坐标和 JSON 时间均不改动。关闭平台后电脑上的浏览器视频缓存保留，下次无需重复下载或转码；移除本机项目会释放该项目当前电脑和服务上的临时播放缓存并隐藏列表项，保留平台项目和 NAS 副本。

标注页面的播放、倍速、时间轴封面和悬停图片均使用本机精简缓存，不在每次点击时读取共享目录。原目录和本机的缓存文件夹均有 README.md 说明；缓存不是原视频备份。本机素材尚无可用视频缓存时需连接原磁盘完成首次准备；已有有效精简视频时可在本机补齐快进和图片。内网 NAS 素材需要补齐时经 Ubuntu 处理；网页模式首次选择并授权桌面缓存目录，进入工作台前完整保存普通、倍速视频和全部图片到该目录，重新打开仍须登录并校验项目状态，已有完整浏览器缓存无需重新下载视频。公网 S3 素材仍需单独部署和验收。

悬停画面使用160×90、每秒一帧的JPEG图集，不再创建第二个视频解码器。连续移动鼠标不等待停稳；同一图集内直接切格，切换图集时保留标明时间的上次画面，初次读取先显示标明为封面的图片。主预览仍按毫秒光标定位。准备页面会在进入标注前补齐缺少的悬停图片；优先复用已有图片，缺少时按素材来源在本机或服务器生成。

工作台固定在一屏内：视频随窗口缩放，右侧标注面板独立滚动；当前启用的场景、姿势、大类预置轴显示在自定义轴之前。主轴及子轴较多时，普通滚轮可纵向滚动整个标注轴列表，时间刻度与视频轴保留在上方，子轴紧随所属主轴显示。

新项目首次打开默认勾选默认库中的时间轴（初始为场景、姿势、大类）。标注面板只提供“选择时间轴”，从账号库勾选本项目使用的轴，不在标注面板创建、删除轴或管理标签；默认轴也可取消勾选，允许全部不选。项目首次使用某轴时保存其名称、类型和标签副本；以后重新勾选沿用原副本，库中的修改或删除均不追溯已有项目。取消勾选只隐藏轴，保留标注和 JSON；库中已删除但项目使用过的轴仍可在选择窗口重新启用；已停用的内置习惯轴除外，其历史数据保留但不再提供入口。选择状态写入本机 SQLite，也随正式 JSON 的 timebase.selected_tracks 写回并在重开时恢复。本地导出为三个固定轴及已有自定义轴的独立 JSON，包括未勾选轴；云端输出仅包含当前勾选轴，两者均跳过习惯轴，每轴一个 JSON；例如云端仅选姿势时只写 posture.timeline.json，未勾选轴的已有文件不覆盖、不删除。最多使用 16 条自定义轴。项目配置、勾选和标注编辑记录持久保存在服务所在电脑的 .local 数据库，面板标题旁可查看最近操作；隐藏时间轴或清理预览不会删除这些记录。

右上角齿轮按钮打开“进度快捷键设置”，可分别调整普通左右键、Shift + 左右键、Ctrl + 左右键、Ctrl + Alt + 滚轮和 Shift + 滚轮的移动步长（0.001–3600 秒，最多三位小数）。点击保存后立即生效，并在当前浏览器记住，适用于所有项目；恢复默认仍需保存。设置窗口保留输入框正常编辑，调整进度会暂停播放。

仅移除姿态标签按钮的 Z/X/C/V 快捷键；坐、站、躺、移动、骑行等姿态通过鼠标按钮选择。其它快捷键保留：空格播放/暂停，普通左右键默认前后 0.1 秒，Shift + 左右键 1 秒，Ctrl + 左右键 30 秒，Ctrl + 空格添加或移除当前锚点，Ctrl + Z 撤销，Ctrl + Shift + Z 恢复，Delete 删除选中色块（输入框正常删字）。时间轴聚焦时 Home/End 跳到首尾。底部不再提供撤销、恢复按钮，两组快捷键保留。

Shift + 滚轮默认每次移动 1 秒，原来保存的其他四组步长不受影响；普通滚轮上下滚动，Alt + 滚轮横向浏览时间轴。

鼠标滚轮操作保留：Ctrl + 滚轮缩放时间轴；Alt + 滚轮横向浏览；Ctrl + Alt + 滚轮默认每次前后 5 秒；Shift + 滚轮默认每次前后 1 秒，上退下进。顶部“工作台全屏”按钮隐藏地址栏和标签栏，Esc 由浏览器用于退出全屏。工作台仍阻止 Ctrl + 滚轮和 Ctrl + + / - / 0 改变浏览器缩放；浏览器及系统保留操作不变。

素材准备阶段，默认最多同时协调 2 段视频，NAS 10443 按 `DATAMARK_PREPARATION_PARALLELISM=3` 同时处理最多 3 段；全部使用服务器的任务不受本机逻辑处理器数量限制，需要本机转码时仍要求电脑至少有 4 个逻辑处理器才启用并行。同一任务内存在重复素材引用时自动逐段处理，避免同时写入同一缓存。本机素材由本机 FFmpeg 生成缺少的精简预览，配置映射的 NAS 素材交由服务器处理；页面显示各段进度，区分检查、复用、NAS 缓存检查、本机生成、服务器处理和下载。已经完成的素材会复用，异常中断后可重试。进入标注后无需重新转码，并提前载入下一段本机视频。点击或拖动时间轴时只在松开后定位一次，拖动过程中更新光标；高倍速下手动调整进度同样暂停并切回普通预览，保留原时间轴精度；拖动过程中不恢复播放。浏览器取消旧的视频读取请求时，后台会停止对应读取，避免过时的传输占用读取资源。已显示的画面在短暂缓冲时保留，超过短暂延迟才显示小提示。本机精简预览降低分辨率和码率、加密关键帧，同时保留原帧时序。原始视频不改动。首次准备仍需读取和解码原视频，因此长素材仍会花费时间。

旧项目若尚未接入时间轴库、仍显示旧版固定标签按钮，打开时会一次性采用当前默认库按钮，并保留历史标注原文、备注、子轴位置和已有勾选状态。已有项目副本及自行定制的标签继续保留；之后库中的修改仍不会追溯项目。旧项目自定义轴已满时保留原轴，不会因自动补入默认轴而无法打开。

## 输出格式

- `scene.timeline.json`：场景轴。
- `posture.timeline.json`：姿势轴。
- `category.timeline.json`：大类轴。
- `habit.timeline.json`：仅兼容历史习惯数据，当前页面的本地与云端输出均跳过该文件，已有文件保留。
- 自定义轴各有一个 JSON 文件：新轴使用创建时填写的名称（如 `food.timeline.json`），旧轴仍使用 `custom_<ID>.timeline.json`；仅在添加该轴的项目中产生。

当前页面使用 `schema_version: 3` 的独立 JSON：本地输出场景、姿势、大类及项目已有自定义轴，包括未勾选轴；云端只输出当前勾选轴。两种输出均跳过已停用的习惯轴，旧 `habit.timeline.json` 不覆盖、不删除，历史习惯标注仍保存在草稿中。没有标注的固定轴以空 `segments` 输出。旧 ZIP API 仅保留给历史或管理员接口兼容，不再作为页面导出方式。平台兼容读取 `schema_version: 1` 的旧三文件和 `schema_version: 2` 的旧四文件；旧标注没有可信的标注人信息，不自动推断。正式输出允许轴留空或只标注部分；云端文件用 `timebase.written_tracks` 标明本次选中轴，保留目录中其他轴的旧文件；重开时逐文件校验并恢复这些保留轴的标注及定义，保留空白、时间轴选择及主轴／子轴关系。

每个文件包含 `schema_version`、共同的保存批次 `save_id`、采集信息、标签表 `labels` 和记录 `segments`。时间单位为毫秒，起点是最早视频的拍摄开始时间；各视频在轴上的位置由文件名中的拍摄时间决定，空档计入总时间跨度。`timebase.videos` 保留各视频相对路径和轴上起止时间，可回溯原始素材。每个文件的 `timebase.fixed_tracks` 记录当前启用的预置轴，`timebase.track_labels` 保留预置轴的项目标签定义（可含历史 habit 元数据）；旧文件缺少字段时使用原默认值。存在自定义轴时，`timebase.custom_tracks` 包含项目轴及其标签清单；对应文件另有 `axis_name` 和 `axis_mode`，重开项目据此恢复自定义轴。

领取目录时，“沿用 NAS 的旧 JSON”允许只有部分时间轴文件：载入现存文件中的标注，缺失的预置轴或已声明的自定义轴保持空白，不从平台旧草稿或根目录另一个批次补齐。轴定义和标签清单从现存文件恢复；普通导入的现存文件须属于同一保存批次；按勾选轴写回后保留的旧轴文件可来自先前批次，重开仍恢复其标注及轴定义，只隐藏未勾选轴，重新勾选不会清空旧文件。同一批次的定义和选择必须一致，所有文件仍须对应同一格式版本和同一素材，时间范围及标签校验照常执行，未声明的自定义轴文件仍拒绝读取。没有任何时间轴文件时不执行旧 JSON 导入。打开目录不补写缺失文件；之后本地导出包含场景、姿势、大类及所有自定义轴；云端导出仅生成当前勾选轴的新批次，其他已有轴文件保持不变。两种输出均跳过已停用的习惯轴。

旧项目的视频原先直接位于采集根目录、后来全部移入同一目录的 `FPV/` 时，重新领取可安全更新项目路径，无需移动 NAS 文件。平台核对整批视频名称、顺序、时间轴、大小及内容抽样摘要与保存记录一致；复制后的修改时间变化和旧位置仍有副本不会单独阻止关联，旧副本不删除。文件有增减或素材身份不一致时仍拒绝关联。确认匹配后，平台先保存含旧路径和草稿的恢复副本，再更新路径及项目版本；原项目 ID、名称、时间坐标和素材历史指纹保持不变。领取时保留平台草稿或沿用 NAS JSON 的选择仍照常执行，正式写回的 JSON 会记录可供重新导入的当前路径指纹。此核验依据原项目保存的文件身份记录，不等于历史原视频的完整内容哈希核验；其他目录迁移仍使用原有的关联流程。

版本 3 的单条 `segments` 记录可包含 `created_by`、`created_by_name`、`created_at`、`updated_by`、`updated_by_name`、`updated_at`。前两个身份字段分别是账号 ID 与保存时的显示姓名；时间字段为 UTC ISO 8601。已有历史不完整的记录可缺少这些可选字段。独立的编辑历史保存在本机草稿数据库，不加入导出的 JSON。

每条标注还包含现实时间 `start_time`、`end_time`，采用六位字符串 `HHMMSS`，例如 `"150456"` 表示 15:04:56，`"000005"` 表示 00:00:05。这些时间根据最早录制时间加对应毫秒偏移换算，保留录制间隔；同时输出 `start_date`、`end_date`（`YYYY-MM-DD`）区分跨午夜记录。时区为 `Asia/Shanghai`；现实时间显示到秒，原始毫秒字段保留精度。历史零时长记录的两组时间相同。原有草稿无需修改，重新导出或写回即可得到新字段。

区间记录使用 `kind: "interval"`，起止语义为 `[start_ms, end_ms)`；历史零时长记录使用 `kind: "point"`，`start_ms` 与 `end_ms` 相同，继续兼容读取、保存和导出；界面不再提供新增入口。每条记录保存 `lane`：`0` 为主轴，正整数为子轴编号。任意轴均可在不同 lane 上标注重叠或相同状态，同一 lane 内不允许冲突；子轴与主轴保存在同一个时间轴 JSON，不另建文件。旧记录缺少 lane 时按时间顺序分配到可用层，保留原标签；已有明确编号不会重排。旧大类 `mode: "overlay"` 区间保留兼容读取；新大类区间写入 `mode: "state"`。草稿允许未标注空白及尚未结束的事件 `end_ms: null`；正式导出和写回允许轴留空；本地导出要求所有本次输出轴的事件区间结束，云端输出仅要求本次选中轴的事件区间结束；已停用的习惯轴不参与这两种输出。

目录模式写回前会检查源素材与已有 JSON 是否发生外部修改。NAS 中已删除的已勾选时间轴 JSON 会按当前平台草稿重新生成；已有文件若被改写，或出现平台未记录的新文件，仍会提示冲突并停止写回。被替换文件的旧版本保存在原目录的 `.annotation-backups` 中。只有显示云端导出已完成且已读回核验，才表示目标目录保存成功；“已保存到平台”表示 SQLite 草稿已保存。

### 相机分段的秒级时间误差

`A09999_YYYYMMDDHHMMSS_序号.avi` 的文件名只能给出整秒时间，视频时长仍按帧计算。例如 13:11:35 开始的素材长 600.533 秒，而下一段名字为 13:21:35，会出现 533 毫秒的名义重叠。对同一相机、相邻序号、递增的秒精度时间戳，若原始相邻边界重叠和累计校正均不超过 3000 毫秒（含 3000），且原始名义间隔不足 1000 毫秒，平台将下一段接在上一段实际结束处，保留每段全部帧和原文件。单个原始边界重叠或累计校正超过 3000 毫秒、不同相机、序号不连续、时间相同或明确带毫秒的时间戳仍按严格规则检查。两个上限分别用于限制单段误差与连续片段的累计偏移。

相同相机、连续序号的正向亚秒接缝也按秒精度误差判断：实际接缝与原始相邻边界误差均不足 1000 毫秒，且相邻片段校正量均不超过 3000 毫秒时，按连续录制标注。视频条在接缝处连续显示，场景、姿势、大类和自定义持续事件可跨文件保存为完整区间。尚未保存主轴、子轴编号的旧场景／姿势若恰好在这类接缝结束，并在紧接的文件中以同标签重新开始，打开时会接续为一条。所有轴中首尾相接、完整标签（含备注）和模式相同的持续区间，均在各自主轴或子轴内自动合并，保存时间或操作者不同不影响合并；已有不同子轴上的记录不会自动搬移，锚点新增内容则按前述规则逐层归并；不同备注、历史零时长记录和真实空白保持独立，原始编辑记录仍保留。真实断录不合并。导出 timebase 的 recording_runs 和 continuity_bridges 记录连续范围及判断依据，已有视频坐标和标注时间不移动。

这是在允许误差范围内作出的时间对齐估计，并非确认真实拍摄时间完全连续。原始名义间隔达到 1000 毫秒时，不用此前累计偏移强行接续。导出规则使用 v2，明确区分重叠和累计偏移的 3000 毫秒含端点上限与名义间隔的 1000 毫秒不含端点上限；导出保留原文件名时间、名义起点、对齐偏移和使用的规则；导入提示会列出校正次数与最大偏移。没有录制的长间隔继续保留，间隔后的下一段仍以文件名时间定位；前段若有偏移，间隔长度会相应变化。原有无偏移项目的时间轴不变。

可通过“新建项目”选择本机视频或填写路径（例如 `E:\VIDEO`）；选择文件与选择目录都不会复制原视频。


高倍速预览在素材准备阶段从精简视频生成，最终存放在本机播放文件夹；配置映射的 NAS 素材在服务器生成后随缓存包下载，本机素材仍可复用已有原目录倍速缓存。

## 项目名称、存储与删除

新建项目时可填写名称；选择目录并留空时，直接使用所选文件夹名（选择 `FPV` 子目录时即使用 `FPV`）。单独选择视频文件并留空时，仍按首次导入时间（北京时间）生成，例如 `0914-20-32`。展开项目下拉后，每个项目右侧的铅笔按钮可修改该项目名称；名称最多 80 个字符，自动去除首尾空白。允许同名项目，由内部独立 ID 区分。重命名保留标注、播放位置、锚点、当前输入和撤销记录，不移动原视频或缓存；之后导出及写回使用新名称，已导出文件不会自动修改。再次读取已导入的原目录会打开原项目并保留原名称。旧项目启动时自动迁移，缺少首次导入时间的，依据最早可查的本地导入目录或缓存创建时间补齐，并记录 `import_time_estimated`。

`.local/projects/<项目ID>/` 保存项目准备记录、旧版 `playback/` 精简播放缓存和桌面缓存索引，新版媒体保存在桌面目录，标注草稿存于 `.local/annotations.sqlite3`；原视频及完整预览缓存留在原素材目录。旧的目录引用项目在原目录可读写时迁移已有缓存；旧上传项目点击“关联原目录”，核对全部同名原视频、大小和完整文件内容一致后，复用并迁移已有缓存，更新路径，最后清理平台中的已核验重复副本。原目录未知、缺失或内容不一致时不删除旧副本，已有标注、视频编号和时间坐标保持不变。

展开项目下拉后，每个项目右侧的垃圾桶按钮用于清理预览并移除本机项目。确认后停止该项目的素材准备任务，按项目引用清理此电脑已登记的桌面播放缓存，并兼容清理旧浏览器及项目内部 `playback/` 副本；清理成功后，在当前浏览器按账号持久记住隐藏状态，项目不再出现在本机列表中。平台项目记录、SQLite 标注草稿、浏览器输入草稿、旧上传副本、原视频、NAS/S3 缓存包、原目录完整预览及 `timeline/` 结果全部保留，不删除整个项目目录。即使 NAS 离线也可清理；文件被占用时明确报错，可关闭播放窗口后重试。清理会暂停各标签页的准备和播放，并取消该项目自动恢复；刷新不会重新下载刚清理的预览。需要继续时，从“新建项目”重新选择原素材即可恢复原项目及草稿；NAS 项目复用已校验缓存，无需重压缩原视频。隐藏仅作用于当前浏览器的当前账号，不等于平台永久删除。原永久删除接口仍停用。

## 导入姿势 JSON

进入工作台后，在右侧“标注输出”中点击“导入姿势 JSON”，选择文件后直接写入当前项目的姿势主轴，并自动保存平台草稿。支持 `imu_fusion_prediction_timeline/1.0.0` 预测时间轴及同结构文件：`axis` 为 `posture`，`timebase.recording_start` 为完整日期时间，`timebase.unit` 为 `ms`，`segments` 包含 `label`、`start_ms`、`end_ms`，区间已结束且无主轴重叠。单文件上限 20 MB / 50000 条；请先勾选项目姿势轴；编辑备注后按 Enter 或离开输入框完成保存。

导入使用 JSON 录制起点加区间毫秒坐标所表达的实际时间，只转换为当前项目的时间坐标；不进行动作对齐，不应用 `recordings[].camera_minus_imu_offset_s`。每个导入区间仅保留与项目实际视频重叠的部分，跨越无视频断档时拆开；有视频但 JSON 没有标注的部分不补齐、不修改原标注。仅替换导入区间覆盖到的已有姿势主轴内容，保留子轴和其他轴，支持一次撤销整个导入；正式导出和写回仍使用平台原有格式与操作。导入完成后显示保留的段数、时长及舍弃的无视频时长。非法文件或完全无视频交集时不修改项目。


### 共用任务管理（默认关闭）

NAS、本机模拟和公网使用同一个任务模块及现有标注工作台，素材来源由存储适配决定。传统项目流程仍保留。任务标注工作台按已发布规则分别保存固定轴标签与自定义轴定义；自定义轴标签不混入固定轴清单。旧任务工作台若含此类混合配置，重开时修复定义存储，保留任务规则、草稿和提交记录。任务管理不改变现有账号库、NAS 项目分配、JSON 格式或源目录写回；任务角色、规则、草稿、提交版本和日志单独持久化。任务工作台不会把标注写入传统项目草稿，也不提供直接写回原目录。

`DATAMARK_TASKS_ENABLED` 默认为 `0`，关闭时没有任务入口、接口注册或任务数据库初始化；`/api/tasks/` 返回 404。启用时必须配置两个可写绝对路径：`DATAMARK_TASKS_STATE` 保存独立 `tasks.sqlite3` 及工作台媒体准备状态，`DATAMARK_TASKS_ARTIFACTS` 保存不可覆盖的提交、最终版本及交付文件。不能使用软链接路径。健康接口声明 `task-management` 能力后，同一个前端构建才显示“任务管理”。角色授权仍需超级管理员操作，管理员和组长拥有完整任务管理、标注、复核、裁定、验收及交付导出权限，无需另授标注员或复核员角色，可被分配为标注人并复核、裁定、验收自己的标注；开启不会将旧项目自动转换成任务。

启用任务管理后，超级管理员的“账号管理”使用邮箱作为新账号，填写姓名、选择标注人／组长／复核员角色（可多选），初始密码预填 `1234567890`，可修改。创建后按“姓名｜邮箱账号｜任务角色｜是否开放上传”显示，列表支持部分姓名搜索和角色筛选组合使用，多角色账号按任一匹配角色显示，角色变更统一在账号管理中进行，任务管理不再设置重复的授权标签；点击角色文字可唤出选择窗口，直接修改已有账号的任务角色，支持多选、保存和取消，全部取消则撤销任务权限；新建账号或保存角色时，包含组长默认开放上传，其他角色默认关闭；之后超级管理员可在列表的“已开放／未开放”下拉菜单中单独调整；保留停用和密码重置功能。仅超级管理员可删除账号，列表提供确认窗口，三种任务角色均无删除权限；删除后账号移出列表并立即失去登录权限，历史身份、任务、标注和记录保留，原邮箱账号不复用，不能通过启用操作恢复；不能删除当前登录账号或最后一个有效管理员。公网通过私有账号桥写入原 Ubuntu 账号库，不建立另一套账号库；新账号使用邮箱登录，旧账号仍可正常登录，不自动改名或重设密码。任务角色在当前部署的任务库中保存，不改变旧 NAS 账号角色。账号创建与任务授权跨两个存储，授权失败时明确报告账号已创建、需补设角色；角色保存后上传权限更新失败也明确提示重新保存或单独调整，不重复创建或删除账号。任务关闭时仍使用原有账号面板。

任务管理各标签共用固定宽高的面板，随浏览器可用空间缩放；标题和标签栏保持可见，仅下方内容上下滚动。切换标签时从内容顶部开始，长表单不撑大外层窗口。任务分配页按“选择视频、规则与期限、人员分配”分组，宽窗口左右排列，窄窗口纵向排列；底部统一创建任务，待分配模式禁用人员选择。创建并分配后显示成功数量，仅创建待分配任务时显示待分配数量；批量中途失败显示已完成数量和失败视频，成功后刷新失败不提示重复提交。超级管理员打开面板时立即显示全部五个标签，不等待角色接口；取得权限后，任务、规则、人员、素材和交付数据并行加载，素材目录读取失败单独显示，不阻塞其他内容。

本机开发可将两处路径设为本仓库 `.local/tasks/state` 和 `.local/tasks/artifacts`，仅在启动进程设置启用变量。“素材与质检”提供实际视频导入：本机选择多个原视频或采集目录，NAS／模拟 S3 浏览并导入现有采集目录；复用现有媒体探测、原目录读取、权限及领取确认流程，不启用旧的浏览器视频上传，不复制原视频。NAS 旧 JSON 来源选择和接管确认仍保留；导入素材不会将旧项目标注套用到独立任务草稿。仅有上传权限的账号可导入。导入后，按当前账号已获授权的采集文件夹（如 `1001lixin`）登记，一次填写采集员、日期、场景和质检结论，平台核验文件夹内每段视频的来源及时长，并自动生成稳定编号；所有新增视频在同一事务中保存，失败全部回滚。重复登记会提示；文件夹补入新视频后只登记新增部分，已有登记和质检保持原样，包含其他账号已登记视频时拒绝登记。“素材与质检”页按导入、登记、已登记文件夹组织：宽窗口将导入与登记并排，窄窗口上下排列；标题、卡片、操作按钮和表单风格与规则及任务分配页面一致。任务列表、任务分配、标注规则、验收交付采用同一组页头、卡片、状态文字标签及底部操作区；“查看任务”统一打开居中详情弹窗，显示任务信息、规则、提交版本和操作记录；操作记录、提交／历史版本及项目更新时间统一按北京时间显示为 `YYYY-MM-DD HH:mm:ss`，不显示毫秒或时区代码；仅改变页面格式，数据库、导出及视频录制时间轴仍保留原始精度。待分配任务可在弹窗内分配人员。标注及复核工作台为独立操作入口，不以查看详情代替跳转。任务详情、历史记录和空列表保持相同风格。任务操作权限和交付数据规则保持不变。启用任务管理时，普通账号（包括标注员、复核员及组长）不再显示旧时间轴库和项目自定义轴选择入口；相关库、旧模板及项目选轴写接口返回 403，时间轴统一由任务规则决定。管理员保留旧定义维护与规则复制能力；旧库数据、项目轴副本和已有标注不删除。只读兼容接口和未启用任务管理的旧项目流程保留。已提交及后续阶段的任务，对有复核权限的账号显示“打开复核工作台”；进入现有标注工作台，用主视频和主时间轴查看只读提交版本，在右侧开始复核、填写意见、退回返修、裁定或验收。可切换双方提交和历史版本，切换只影响当前显示，不保存或改写标注员草稿。未提交的复核填写在离页或返回时仍受保护，需提交或清空后返回。普通标注员仍进入原标注入口，复核、裁定、验收权限及版本冲突检查沿用原接口。普通任务账号的“选择项目”只展示分配给自己的标注及复核任务，点击后在页面中央弹出任务选择窗口，背景遮罩并限制焦点在弹窗内，支持关闭按钮、Esc 和点击遮罩关闭，不在侧栏内展开挤占布局；可按采集文件夹、视频、状态筛选，并刷新列表；复核任务尚未完成标注提交时显示等待状态、不可进入。选择任务自动进入对应标注或复核工作台，不恢复旧本机项目，也不提供创建、改名、移除旧项目操作。切换前等待草稿保存，未提交复核填写保留保护。复核侧栏只保留任务选择、当前阶段、版本查看及复核相关操作；不渲染项目管理、缓存准备、标注录入或编辑组件，移除重复的视频编号、规则版本、截止日期及人员说明。复核侧栏显示当前阶段，支持用播放位置设置起止点或直接使用选中色块范围；仅退回时选择返修人员，待裁定时不提供不合法的“通过”操作；已完成复核显示等待验收，避免重复提交。从标注工作台返回任务管理时，先等待平台草稿保存完成并结束保存状态，再跳转，不因正常保存过程触发浏览器离页确认；有未确认的编辑或保存失败时留在当前页提示。关闭、刷新等操作的未保存离页保护继续保留。素材列表按采集文件夹折叠，展开后查看或修改单段视频的质检。文件夹显示视频数和合格、待质检、不合格数量，状态同时使用文字和颜色区分；原登记人可在展开后修改单段质检。创建任务以完整采集目录为最小单位，每个文件夹仅有一个选择框，一个采集对应一个任务，统一绑定人员、规则、截止时间、草稿、提交和复核；可展开查看包含的视频，不再逐段勾选或分别创建任务。必须登记完整采集中的全部视频，实际分配时每段均须质检合格；任何一段失去合格状态会阻止该采集继续提交或验收。服务端按当前源项目核对完整视频清单并保存任务素材快照，后续新视频不自动加入已有任务，旧任务的成员和时间坐标不会悄然改变。任务工作台按原项目录制起点、各视频起止时间及真实断档打开完整采集，标注使用整次采集的统一毫秒坐标；草稿和正式输出都禁止位于或跨越无视频断档。旧逐段任务仍能按原坐标读取，不自动合并或改写提交；同批素材存在未删除的同类型旧任务时，新建完整采集任务会拒绝，需先由管理人员按原逻辑删除旧任务，历史和审计保留。登记成功和创建／分配任务成功均弹窗确认；通用成功弹窗采用独立的深色圆角卡片、绿色完成图标、居中正文和确认按钮，支持关闭按钮与 Esc，发布规则等新增操作沿用同一提示；部分任务创建失败时显示已完成数量及失败视频，不显示全部成功。原逐视频 CSV 模板及登记接口保留兼容，CSV 逐项报告结果，不声称失败批次已全部成功。登记和修改质检要求现有上传权限；质检只能由原登记上传人修改，未合格的素材不能分配或继续完成任务。

超级管理员和组长使用“任务列表｜素材与质检｜任务分配｜标注规则｜验收交付”，普通标注人和复核员保留“我的任务”；管理员出现在标注人候选中，被分配后可保存草稿、提交和返修；未分配给自己的任务工作台仍只读，提交后按相同规则锁定。

任务按完整采集文件夹与任务类型分配；规则可从现有时间轴库复制，包含一条或多条轴，发布后内容不可变；仅超级管理员可通过居中确认弹窗删除已发布规则（支持取消和 Esc 关闭），删除后从规则清单及新任务选项中移除，后台保留原版本和删除操作人、时间，已绑定任务继续标注、复核及交付，历史标注不受影响；组长、标注员和复核员无删除权限。复制不修改原库。任务模块支持标注员、复核员、组长多角色；超级管理员通过真实账号列表授权，分配时校验账号有效且有对应任务角色。管理员和组长均可在同一任务中兼任标注人与复核员，并复核、裁定、验收自己的标注；普通标注员和复核员不能自我复核、裁定或验收。双人草稿独立，双方本轮提交前不得读取对方版本；撤销任务角色后立即失去任务访问权限。提交后版本只读，返修创建新草稿，原提交和最终版本保留在历史中。超级管理员和组长可在任务列表通过确认弹窗删除任意阶段的任务；删除需要匹配当前任务版本，删除后停止标注、复核、裁定、验收及新交付，默认列表不再显示，同一视频与任务类型可重新创建。管理人员可勾选“显示已删除任务”只读查看历史。删除保留原始素材、草稿、不可变提交及最终版本、已有交付文件和操作日志，并记录删除人、时间及删除前状态；普通标注员和复核员无删除权限，已删除任务不能继续操作。

任务允许空隙和不同子轴重叠，仍遵守同一子轴内的区间冲突规则。最短持续片段时长和切点比较容差由规则配置，未配置不增加最短时长门槛。新规则边界容差默认“不限制”（保存为 `null`），不自动比较双人结果，由复核员人工判断；仍保留标注员主动标记的待复核项，以及复核、裁定、验收的原权限和版本校验。选择“设置边界容差”后可填写非负毫秒值，0 表示严格比较；已有规则及任务保留原数值，旧记录缺字段仍按 0 比较。“已发布规则”和“发布新规则”默认折叠，点击各自标题独立展开；规则编辑页按基本信息、时间轴配置和选填交通工具要求分组，时间轴类型保持状态和事件两项；最短标注时长默认选择“不限制”，切换为“设置最短时长”后才填写毫秒值，已有发布规则的限制不变。标签、整数毫秒范围、事件闭合、交通工具类型和待复核原因在提交时校验，并可定位片段；草稿允许尚未结束事件或尚未填写提交字段。复核、返修、裁定、验收和交付使用版本校验；尚未解决的意见或分歧不能验收。复核工作台初次只读取当前任务和角色，历史版本展开时再核验读取；开始或提交复核直接采用接口返回的已核验任务，避免重复请求同一批 S3 提交与历史结果。“开始复核”提供醒目的主按钮和即时处理中反馈，提交复核、退回、裁定及验收成功后弹窗提示，失败保留填写。复核完成时任务列表、详情及选择窗口显示“待验收”；管理员和组长即使本人参与标注也提供验收入口，普通角色不提供验收入口。复核界面共享视频播放头，并排展示双方时间轴，高亮并定位差异。明确选择通过或退回，通过时也可记录带时间范围的意见，退回必须填写问题并指定人员，标注工作台显示每处返修意见并可点击定位；重提后复核员逐项确认已处理意见，原提交保持只读；意见与操作人、时间写入不可变日志。任务详情显示采集员、标注员、复核员、裁定人，选择片段可查看对应标注人和提交版本；裁定保留双方提交并另存最终结果与贡献者。完整采集的提交、返修、复核、裁定及验收均按整个任务流转；交付 CSV 保留兼容的 `video_id` 字段（采集内首段登记编号），另含 `collection_id`、`collection_name`、`video_ids` 和 `recording_start`，其片段时间均为整个采集录制起点的相对毫秒，而非首段视频内时间。

只对已验收且版本一致的任务创建交付批次，CSV 使用单视频原时间轴（秒值一位小数并保留原始毫秒），保留子轴与空白语义。字段包括视频、任务类型、规则、轴、片段、子轴、起止时间、标签、交通工具类型、标注人、复核人、裁定人、采集员、上传人及最终版本。保存后读回核验成功才进入已交付；下载再次核对文件大小和摘要。审计日志记录操作者、时间和版本，只追加，数据库触发器禁止修改或删除。任务参与者可读取本人可见任务的操作记录，全局日志仅组长可读。应备份整个任务状态及版本目录；应用层不可变约束不等于抵御宿主机管理员篡改的存储锁定。

完整采集任务的草稿、提交和复核沿用工作台相同的录制连续性规则：只有同相机、连续文件编号且符合秒精度时间误差及校正偏移上限的相邻接缝可连续标注，真实断档仍禁止跨越。旧任务按已冻结的视频名称、录制时间和坐标重新计算连续区间，不移动标注或视频，不要求删除重建任务。

S3 任务结果同时保存到原采集目录的 `timeline/`，结构如下（姓名仅为示例）：

```text
daily/日期/采集目录/timeline/
├── 张三/
│   ├── v1/  # 第一次正式提交的逐轴 JSON
│   └── v2/  # 返修后再次提交的逐轴 JSON
├── 李四/
│   └── v1/
├── finally/  # 管理员或组长验收通过的统一最终逐轴 JSON
└── delivery-<交付批次ID>.csv
```

每个版本按任务规则输出 `scene.timeline.json`、`posture.timeline.json` 等独立文件，沿用现行 schema_version 3，包含真实录制起点、毫秒区间及子轴；规则中的空轴输出空 segments，未使用轴不补写。版本号按同一采集、同一账号递增，返修只新增该账号版本；姓名目录绑定账号身份，同名账号加身份后缀，账号改名继续使用原目录，CSV 保留姓名、身份、目录及提交版本的对应关系。无法取得旧账号姓名时使用账号 ID，不猜测姓名。

正式提交保存个人版本，管理员或组长验收后才保存统一的 `finally/`；仅复核通过不发布最终目录。生成交付批次后在 `timeline/` 下保存该采集自己的 CSV，记录最终版本、分段贡献者、全部标注员、复核/裁定/验收人员及个人版本对应关系；同批次的其他采集不会混入此文件。全空任务也保留一行可追溯的交付记录。个人版本及 CSV 不覆盖，统一最终 JSON 采用版本条件写入，保留既有内部不可变结果与审计；外部修改或未知同名文件不覆盖。

结果目录同步计划与任务变更一起持久化；S3 同步失败时已提交/已验收任务与计划保留，界面明确显示未同步并提供“同步采集结果目录”，重试及服务重启不重复增加版本号。已有 S3 采集任务可通过该按钮补齐历史提交、已验收最终结果及已有交付 CSV，原内部结果保持不变；已删除任务停止同步。文件逐项读回核验后才显示同步完成，个人版本另有隐藏完成清单，`finally/` 也保存隐藏结果清单。此同步仅用于具有完整采集身份的 S3 任务；NAS、本机传统项目和桌面播放缓存的保存位置沿用原规则。

共用任务接口位于 `/api/tasks/`：`me/users/roles/rules/axis-library/sources/videos/items/deliveries/audit`，任务详情下提供独立草稿、提交、分配、复核、裁定、验收和历史接口；媒体与工作台操作也在任务授权范围下检查，不能使用原项目接口绕过任务隔离。所有数据修改仍校验登录、CSRF 与当前任务权限。

公网启用使用覆盖文件 `deploy/compose.tasks-public.yaml`：准备权限受限的持久目录，通过 `DATAMARK_TASK_STATE_DIR` 和 `DATAMARK_TASK_ARTIFACT_DIR` 指定宿主机位置，再叠加对应文件。公网仍需接入真实 S3 才能使用素材与标注业务。

NAS 部署直接在持久 `intranet.env` 中设置 `DATAMARK_TASKS_ENABLED=1`，由现有 Compose 与 Jenkins 发布流程读取，无需叠加文件；默认值仍为 `0`，现已支持按部署授权启用。任务数据库和结果分别保存到 `DATAMARK_HOME/state/tasks/state`、`DATAMARK_HOME/state/tasks/artifacts`，后续重发版保持开关与数据，数据库在线备份同时包含已有任务数据库。独立部署仍可使用 `deploy/compose.tasks-intranet.yaml` 指定其他目录，使用该覆盖文件时须始终叠加相同配置。启用不会自动迁移旧项目或授予普通账号任务角色；任务结果不写回旧项目的 timeline 文件。

公网使用共享账号服务，没有 NAS 挂载；R2 未配置时可启用角色、规则和任务管理页面，但素材清单及登记明确返回 503，不能打开标注。启用 R2 配置后，任务素材使用 R2 压缩视频，任务结果通过同一对象存储保存；代码测试不表示真实桶已接通。公网业务验收必须在真实 S3 配置完成后，用授权账号从外网完整执行分配、标注、复核、裁定、验收和交付。

### 内网使用公网已发布规则

启用 `DATAMARK_TASK_RULES_PUBLIC=1` 后，内网通过公网现有规则接口读取、发布和删除规则，以公网当前规则为唯一来源。使用当前登录账号的共享会话，并同时校验内网角色和公网任务权限；没有公网任务角色时由管理员补授，不扩大原有权限。公网仍使用原有规则存储及接口，不迁移规则、任务、草稿或提交。

内网旧规则不再进入可选列表，但已有任务继续沿用其原规则。内网新建任务前读取当前公网规则，按原编号保存不可变副本，规则后续删除及公网接口故障均不影响已有任务继续标注和验收。公网接口不可用时，规则操作及新建任务明确失败，不回退旧规则列表；发布请求中断时先刷新核对结果，不自动重试以免重复发布。任务、任务角色、草稿、提交和交付仍分别存储。

内网发布脚本按持久 `intranet.env` 中的开关叠加 `deploy/compose.task-rules-intranet.yaml`，仅让内网后台接入既有 `datamark-public-setup_private` 网络；仅代理固定规则接口，不挂载公网数据库，也不代理公网任务及素材。首次使用 `python3 -m deploy.prepare_public_rules --commit <本次发布完整提交号>` 预检，加 `--apply` 在线备份内网任务及两端配置后保存开关。本次提交通过公网持久配置 `DATAMARK_PUBLIC_SKIP_COMMIT=<同一提交号>` 保留当前公网容器；公网发布阶段仍核验现有挂载、健康和登录，仅明确跳过该提交的公网更新，不停止服务、不改变公网发布指针。其他提交的正常公网发布规则不变。准备配置后应立即发布该提交并核对内网规则及公网容器 ID、启动时间未变；取消启用会重新显示内网保留的旧规则列表，须按变更流程处理。

## 上传时生成姿势预标注

此功能将原始视频留在上传人电脑上，由独立 Ubuntu 算法服务处理 IMU、选择校时窗口和生成预测。本机只回传选定窗口的运动曲线。压缩视频、IMU 和 `prediction/posture.json` 经现有校验一起发布，预测与人工 `timeline/`、任务提交及验收结果分开保存。

启用后，在“上传采集文件夹”中选择完整目录，勾选“上传前生成姿势预标注”，明确填写胸部和大腿 IMU 设备编号，再开始上传。不能只选择 FPV 子目录。旧算法单段失败、或整批无可用预测时停止本次上传并显示任务诊断编号；新算法部分成功时保留全部原始素材、上传可用预测，并明确列出未完成记录，不能当作全部预标注完成。已有预测拒绝静默覆盖。仅上传素材或保留已有预测时取消勾选。命令行入口也可使用 `python -m backend.r2_upload --predict --chest-device <编号> --thigh-device <编号>`；旧本机窗口提供相同选项。

算法服务声明支持跨记录校时后，上传页面提供默认未勾选的连续时钟确认；只有确认本次全部记录使用的胸部设备与相机未重启、换机或调时，才允许短记录参考同日其他记录的可靠偏移。未确认时各记录独立校时；不按目录名或设备编号猜测时钟连续。命令行可显式传入 `--clock-group <连续时钟批次标识>`。继承的校时结果始终要求人工复核。

1.3.0 预测须包含一致的批次状态、成功数量、未完成记录及来源清单。上传助手在发布预测前核对任务响应、文件摘要、原 IMU 摘要与本次输入清单；页面在素材上传成功后仍显示部分预标注状态、未完成文件及原因。项目和独立任务保存这些信息，重开仍提示缺失区间待人工标注；人工草稿保护和真实断档规则保持不变。新旧算法服务可分别返回 1.3.0 或 1.2.0，无须同时切换；本机上传组件也须更新以传递确认和展示新结果。

设备编号可填写唯一简称（如 `WT901BLE67`），或带地址的完整名称。地址支持下划线与冒号两种写法，例如 `WT901BLE67(F9_07_E6_4C_66_D3)` 和 `WT901BLE67(F9:07:E6:4C:66:D3)`；上传组件统一将括号内地址转为冒号格式后提交算法，不修改原文件或设备名称其他部分的下划线。填写时不含 `.wplay` 扩展名；同一设备的两种写法不能分别指定为胸部和大腿。

算法服务来自独立 `IMU_posture` 仓库的远程协议 1。上传组件从算法服务通过平台代理获取仅使用标准库的本机采样工具，并核验摘要，不安装 NumPy／模型依赖。平台代理逐次检查当前会话、上传权限和任务所属账号，服务凭据只保存在后台。

后台默认关闭远程生成。启用需配置 `DATAMARK_PREDICTION_URL`（私网算法服务地址）和 `DATAMARK_PREDICTION_TOKEN_FILE`（受保护的只读凭据文件），私网服务不开放公网端口。`deploy/compose.prediction.yaml` 是显式启用用的可选 overlay，需预先提供固定算法镜像、UID 1000 可写的持久任务目录和受控凭据文件。现有 Ubuntu 算法容器 `imu-posture-worker` 可通过独立的 `compose.prediction-external.yaml` 接入，无需重建算法服务；在公网持久 `runtime.conf` 中显式设置 `DATAMARK_PREDICTION_EXTERNAL=1` 后，Jenkins 公网发布自动保留该连接。凭据仅只读挂载现有受保护文件，算法端口不对公网开放，部署后验证真实私网能力接口，失败回滚公网 API。首次接入需先核对网络、挂载及当前业务窗口，普通发布仍禁止改变已有持久挂载；未启用时保留原行为。 合并代码本身不会启动算法服务或修改公网入口。

完整发布的采集可携带 `prediction/posture.json`。新建项目在首次初始化时间轴库后，只有全空且没有人工草稿、原 timeline 或写回记录时才自动初始化姿势。已有项目不会追溯导入；明确从空白重新开始也不会重新灌入预测。任务使用自身冻结规则，在标注员首次打开且尚无草稿／提交时初始化其独立草稿；复核人不产生预测草稿。人工清空或编辑后重新打开不会再次导入，返修、正式提交和已验收结果均保留。

自动导入兼容 `imu_fusion_prediction_timeline/1.2.0` 与 `imu_fusion_prediction_timeline/1.3.0`、相机毫秒坐标、合法姿势主轴区间及原始视频时间清单，最多 20 MiB／50000 条源区间。S3 从已发布清单指定对象读取并核对大小与摘要，并将预测声明的 IMU 摘要与该采集附件核对；NAS／本机读取同目录预测并核验对应 IMU 原文件，不改原文件。按原视频逻辑名称对应压缩 MP4，并采用项目已确认的逐视频起点和时长映射，保留真实断档；相机／IMU 偏移不再应用。缺少校时信息、素材不匹配或标签不符合任务规则时保持空白并显示原因。导入来源摘要、部分成功清单和校时复核状态随草稿保留，未确认校时显示提示。

测试覆盖独立数据库、Mock 存储、权限撤销、源文件变化、重复准备、草稿保护、视频断档和相邻视频时间修正。额外的跨仓库合成检查由 `IMU_posture/scripts/check_remote_datamark.py --datamark-root <本仓库>` 驱动 `scripts/check_prediction_integration.py`，运行真实算法、自动校时、压缩、Mock 上传及项目／任务导入；该结果不代表真实 S3 或真实采集数据验收。旧纯视频 `MockUploadManager` 流程保持原样，本次生成接在完整采集目录的 `FolderUploadManager` 上传链路。
