# DataMark 视频标注工作台

Ubuntu 内网部署是现行主服务，本机模式用于开发和旧数据处理。平台支持多账号视频标注，React + TypeScript + Vite 前端与 FastAPI 后端由同一服务提供；本机地址为 **http://127.0.0.1:8765**。Ubuntu 内网入口使用 HTTPS，不开放到公网。

本文件是当前安装、使用、数据格式与维护说明。人工 GT 按事实核对，目录分类和采集计划不会自动成为标签；时间轴空白表示未标注，不表示行为没有发生。IMU 对齐、采集总览和模型评估尚未实现。

## 启动与停止

Windows 本机已配置项目内运行环境时，双击项目根目录的 **启动标注平台.lnk**；macOS 本机已配置项目内虚拟环境、前端构建和 FFmpeg 工具时，在项目根目录运行 `.venv/bin/python launch.py`。两种方式都会启动后台服务并自动打开浏览器。关闭最后一个标注网页后，服务会在约 15 秒后自动退出，并停止未完成的预览生成；下次打开可继续准备。刷新页面、网页在后台或其他标注标签页仍打开时不会退出。已有服务时再次启动只打开网页，不重复启动服务。

服务停止后，普通浏览器无法仅靠访问网址唤起本机程序；再次使用请在 Windows 双击启动快捷方式，或在 macOS 重新运行启动命令。日志保存在 `.local/logs/server.stdout.log` 与 `server.stderr.log`。

更新平台代码后，刷新网页只会更新页面，不会重启后台服务。先让进行中的导入／准备任务完成，再关闭所有平台网页，等待约 15 秒后按对应系统的方式重新启动，前后端即可一起使用新版本。已完成的缓存和标注会保留。

Windows 首次重新安装或更新源码后，先运行 **setup.cmd**。脚本使用本机已有 Python 和 Node，创建 `.venv`、按锁文件安装依赖、校验 FFmpeg 下载并构建前端；不修改永久 PATH、用户级包管理配置、系统服务或 PowerShell 执行策略。命令行方式：

```powershell
.\setup.cmd
.\启动标注平台.lnk
```

首次安装时，`setup.cmd` 会在控制台提示创建管理员账号和密码；密码输入不会显示，也不会写入命令历史。若使用现有环境手动更新，可运行 `.venv\Scripts\python.exe -m backend.auth` 创建首位管理员，再启动平台。没有有效管理员时启动程序会拒绝提供标注服务。不要在聊天、代码或文档中填写密码。

## 账号与项目权限

登录后才能读取项目、预览素材、保存草稿或导出。管理员总览全部 NAS 项目，可新建标注账号、停用或启用账号、重置密码，并在需要时调整项目领取人。标注员不必等待管理员分配：从 NAS 选择完整采集目录后，未领取项目由第一位标注员领取；其他标注员不能打开或重复导入其中视频。每个项目只有一位标注员领取，管理员仍可查看和编辑。管理员与领取人同时打开项目时，页面显示其他在线编辑者；草稿保存还核对项目版本，旧版本不会覆盖新版本。突然断开的在线提示约 45 秒后过期。标注员可对自己领取的项目补导入、跳过或恢复准备失败的视频、写回原目录。关联原目录和重命名仍由管理员操作。停用账号或重置密码会立即撤销该账号已有登录。任何用户都可在页面上修改自己的密码，修改后需要重新登录。

密码采用带独立随机盐的 scrypt 哈希保存于 `.local/auth.sqlite3`，登录会限制连续失败次数。登录使用 12 小时会话，浏览器只持有不可由 JavaScript 读取的会话 Cookie；修改接口另检查页面安全令牌和来源。本机启动器仍只监听 `127.0.0.1`；Ubuntu 内网部署按下文配置独立 HTTPS 入口。公司邮箱验证码暂缓；公网入口按下文的 Vercel 网页与 Ubuntu 接口拆分方案单独启用，不要把本机服务端口映射到公网。

每次保存草稿时，服务端根据当前登录账号记录标注的创建者、创建时间、最近编辑者和最近编辑时间；客户端提交的这些字段不能覆盖服务端记录。选中标注可查看其归属，页面可打开编辑历史查看新增、修改、删除和撤销引起的变更。旧版标注没有可验证的操作者，显示为未知。浏览器内尚未提交的习惯输入按账号隔离；有未保存编辑时会阻止直接退出登录。停止服务后备份 `.local/annotations.sqlite3` 与 `.local/auth.sqlite3`，两者分别保存草稿及编辑历史、账号与项目分配；不要提交到 Git。

验证环境：Python 3.14.6、Node 24.18.0。运行时记录见 `runtime-manifest.json`，Python 全部依赖锁定在 `requirements.lock.txt`，前端依赖锁定在 `frontend/package-lock.json`。`setup.ps1 -SkipFrontend` 只检查／安装后端和 FFmpeg，不重建前端。

## Ubuntu 内网部署

`deploy/compose.intranet.yaml` 部署网页服务和独立 HTTPS 网关，原有 `deploy/compose.yaml` 仍只负责视频处理服务。该内网网关端口只绑定 `DATAMARK_BIND_IP` 指定的 Ubuntu 内网地址；网页容器不发布端口。请同时在主机防火墙及网络边界只允许授权内网访问该网关的 443，不要将这个内网入口映射到公网。内网网页只允许浏览和导入容器内 `/mnt/nas/homes/datacollection` 下的采集素材；更换采集根目录时须同步修改 Compose 中的 `DATAMARK_SOURCE_ROOT`，不能指向整个 NAS。部署需要 Ubuntu 已安装 Docker Compose、NAS 已挂载到本机，并确认服务 UID/GID `1000:1000` 对采集素材有读取权限、对标注输出及缓存目录有写入权限；读取和写入须分别验证。

在 Ubuntu 项目目录复制 `deploy/intranet.env.example` 为 `deploy/intranet.env`，填写实际值：`DATAMARK_HOST` 是浏览器访问的内网 IP，`DATAMARK_BIND_IP` 是服务器持有的 RFC1918 局域网网卡 IP，`DATAMARK_HOME` 是应用持久化目录，`DATAMARK_NAS_MOUNT` 是已挂载的 NAS 根目录，`DATAMARK_WEB_IMAGE_TAG` 是本次发布标识。前两项使用 IP 直连时通常相同。已核实 `relty-server` 的 `192.168.2.126` 是固定内网地址，`192.168.2.25` 是同一服务器的动态有线地址；在该服务器部署时使用前者。配置文件不存放密码，实际配置文件已被 Git 忽略。先核对 NAS 挂载和目标目录，再执行：

```sh
install -d /home/relty/services/datamark-web/caddy-data /home/relty/services/datamark-web/caddy-config
docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml config --quiet
docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml build web
```

完成下面的数据迁移后执行 `docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml up -d`。若从空库开始，先创建与 `DATAMARK_HOME` 一致、归 UID/GID `1000:1000` 所有的 `state/`，再通过 `docker compose --env-file deploy/intranet.env -f deploy/compose.intranet.yaml run --rm --no-deps web /opt/venv/bin/python -m backend.auth` 交互创建管理员。管理员密码不写入配置文件或命令历史。启动后检查两个容器健康状态，并从授权内网设备访问 `https://<DATAMARK_HOST>/api/health`、登录、项目分配、预览、草稿保存、导出和 NAS 写回。只有实际读回四个固定 `timeline/` 文件及项目自定义轴文件后才能确认 NAS 写回成功。

网关使用内部证书颁发机构自动签发 HTTPS 证书。首次启动后，从持久化的 `caddy-data/caddy/pki/authorities/local/root.crt` 获取公开根证书，按公司设备管理流程导入每台访问设备的受信任根证书库；私钥和整个 `caddy-data` 目录不得分发。浏览器未信任根证书前，不要通过忽略证书警告输入账号密码。持久化备份应覆盖应用 `state/` 中的两个 SQLite 数据库和项目播放缓存，以及 `caddy-data/`；恢复时先停服务，恢复完整目录后再启动并验证登录与项目读写。

### Jenkins 自动发布

`main` 是 Ubuntu 发布分支。`relty-server` 上的 Jenkins 任务应建为 **Pipeline script from SCM**：仓库地址 `https://github.com/Relty-Dynamic/Data-Annotation.git`，分支指定 `*/main`，脚本路径 `Jenkinsfile`，只允许运行在同机的 `built-in` 节点。Jenkinsfile 使用 `pollSCM('H/2 * * * *')`，约每 2 分钟检查一次；只有 `main` 出现新提交才构建。不要把具有 Docker 权限的此任务用于未合并分支或外部提交。任务创建后的首次运行会注册轮询规则；单有 Jenkinsfile 不会自动创建任务。

首次启用前，由 `relty` 在 Ubuntu 上把当前发布目录中的 `deploy/intranet.env` 复制到持久目录 `/home/relty/services/datamark-web/intranet.env`，权限设为 `600`，并将 `/home/relty/services/datamark-web/current` 链接到已运行的发布目录。配置文件、数据库、证书和 NAS 素材始终留在仓库外。Jenkins 与网页容器使用同一台主机上的 `relty` 账号，且该账号已有 Docker 权限；流水线不会创建管理员或更改系统服务。

每次新提交先在镜像构建中运行前端测试和构建，再在隔离容器中运行后端测试；失败时不触碰运行中的服务。通过后，`deploy/ci-deploy-intranet.sh` 从该提交创建独立发布目录、在线备份两个 SQLite 数据库、仅更新 DataMark 的 Compose 服务，并通过内网证书验证健康接口。健康检查失败会尝试恢复先前容器版本，`current` 链接仅在健康检查成功后切换；成功后也会把持久配置中的网页镜像标识更新为已验证的提交，避免后续重启恢复旧镜像。备份存放于 `backups/<提交>-<时间>/`，不会自动删除；数据库模式不兼容时须人工评估恢复，不能直接覆盖仍在写入的数据库。Jenkins 的测试通过和健康接口正常不等于真实项目的 NAS 写回验收；仍需用授权账号实际标注并读回全部时间轴文件。

### Vercel 网页与 Ubuntu 公网接口

公网网页只在 Vercel 托管构建后的 React 静态文件；账号、项目、SQLite 草稿、NAS 读取、预览生成和写回继续由 Ubuntu 提供。网页 `https://annotate.reltydynamic.com` 与接口 `https://api-annotate.reltydynamic.com:10443` 使用两个独立域名；视频和预览图片从 Ubuntu 接口域名直达浏览器，不经过 Vercel 转发。Cloudflare 只管理 DNS，这两个明确记录须为 DNS only。现有内网 HTTPS 入口与本机启动模式保留。公网入口已启用：2026-10-10 完成可信证书签发、外网 HTTPS 健康检查，用户已在正式域名登录并进入项目页；素材处理及 NAS 写回尚未完成真实业务验收。

Vercel 项目的 Root Directory 为 `frontend`，框架为 Vite，构建命令 `npm run build`，输出目录 `dist`，并设置公开的构建变量 `VITE_DATAMARK_API_ORIGIN=https://api-annotate.reltydynamic.com:10443`。缺少该变量时 Vercel 构建会失败。登录会话 Cookie 仅发给 Ubuntu 接口域名，网页跨域请求明确携带凭据；页面安全令牌由登录响应或已登录状态接口返回。两个正式域名应同属 `reltydynamic.com`，以便继续使用严格同站 Cookie；默认 `*.vercel.app` 预览网址与接口不同站，不能用于已登录流程验收。若需要预览验收，先绑定同站的测试子域名，并将该测试域名配置为后端允许的页面来源。用户已确认使用 Vercel Pro。

先完成真实内网验收及 Ubuntu 公网入站检查：当前路由器将公网 TCP 10443 经过下级路由器转发到 Ubuntu 有线地址 `192.168.2.25:10443`。Ubuntu 上只为该有线地址和 TCP 10443 设置入站放行；Docker 发布端口不能仅靠 UFW 规则隔离。公网 80/443 不可用，因此独立公网 Caddy 使用 Cloudflare DNS 验证自动申请和续期证书。所需 Cloudflare API Token 仅授权 `reltydynamic.com` 的 Zone:Read 与 DNS:Edit，保存在仓库外的 `<DATAMARK_HOME>/secrets/cloudflare-api-token`，由部署用户持有且权限为 `0400` 或 `0600`；不得写入代码、环境变量文件或聊天。域名解析、Token 和入站都就绪后，在持久目录创建归 UID/GID `1000:1000` 所有的 `public-caddy-data/` 与 `public-caddy-config/`，再于仓库外的 `intranet.env` 同时设置 `DATAMARK_PUBLIC_ORIGIN=https://annotate.reltydynamic.com`、`DATAMARK_PUBLIC_API_ORIGIN=https://api-annotate.reltydynamic.com:10443`、`DATAMARK_PUBLIC_BIND_IP=192.168.2.25`。发布脚本只在三项同时设置时启动独立公网 Caddy 网关；该网关仅转发 `/api/`，并以公网可信证书验证健康接口。公网草稿、账号库和 NAS 挂载仍与内网服务共用，不在 Vercel 存储。

启用后须从真实外网使用授权账号核对登录、NAS 目录领取与冲突、精简视频完整下载到浏览器本机存储及本机快进、草稿保存、导出、NAS 写回和全部 `timeline/` 文件读回。健康接口本身不代表业务流程通过。此仓库中的公网本机素材同步和浏览器本机缓存尚未发布或完成真实双端验收，不能描述为已上线能力。

公网标注 NAS 素材时，Ubuntu 先生成精简预览，网页再将普通和倍速 MP4 完整下载到浏览器的本机专用存储，准备完成后从本机播放；封面和悬停图片也在准备时读取。原视频不下载。浏览器需支持 Origin Private File System 且有足够空间；浏览器清除站点数据也会删除这份缓存。提交时先写回采集目录的 `timeline/`，成功后可分别选择清理 Ubuntu 的项目播放缓存、此浏览器的播放缓存，或两者都保留。清理不删除 NAS 原片、NAS 旁的可复用缓存、项目草稿和已写回 JSON。

处理标注员电脑上的素材时，在该电脑运行本机服务，选择原采集目录；原视频和本机播放缓存留在电脑。提交先把正式 JSON 写入本机采集目录的 `timeline/`，再通过已登录的公网账号传给 Ubuntu。Ubuntu 在 NAS 已有的 `/mnt/nas/homes/datacollection/habit/smoking/` 下创建 `<本机采集文件夹名>-<项目ID>/timeline/`，按直接标注 NAS 素材相同的四个固定 JSON 加自定义轴结构写入并读回核验；不上传原视频或本机绝对路径。项目 ID 防止同名采集目录互相覆盖，项目改名不移动已写回目录。此写回使用现有 `DATAMARK_SOURCE_ROOT` 挂载，首次使用须验证服务账号能在 `habit/smoking` 下创建文件。管理员在“账号与项目分配”中查看项目、覆盖进度、NAS 相对目录并下载经 NAS 读回的最终 ZIP。默认接口为 `https://api-annotate.reltydynamic.com:10443`，可在启动本机服务的进程内用 `DATAMARK_CLOUD_API_ORIGIN` 指定另一个已批准的 HTTPS 接口。若 NAS 写回或同步失败，本机 `timeline/` 结果保留，页面提示重新连接和同步；NAS 写回核验前不会按提交选项清理缓存。本机服务与 Ubuntu 服务的账号库分别管理，本机登录后仍须连接公网账号。

现有 Windows 草稿数据库记录了 Windows 原视频绝对路径，不能直接复制到 Ubuntu 使用。**所有用户先保存浏览器中的未提交编辑，停止旧平台并禁止继续编辑**，再在旧机器项目目录运行 `.venv\Scripts\python.exe -m deploy.migrate_projects export --state .local --output <仓库外的安全迁移包目录>`；脚本通过 SQLite 快照备份标注库及已有账号库，并逐个读取原视频计算完整 SHA-256。将整个迁移包经批准的内网传输方式送到 Ubuntu，限制目录权限为仅部署账号可读。按实际 NAS 挂载修改 `deploy/intranet-paths.example.json` 并另存为被 Git 忽略的 `deploy/intranet-paths.json`，补齐其它原视频路径映射。保持 Ubuntu `state/` 不存在，运行 `python3 -m deploy.migrate_projects apply --bundle <迁移包目录> --state <DATAMARK_HOME>/state --mappings deploy/intranet-paths.json`。迁移会逐段比对完整 SHA-256、核对原 `timeline/` 文件，保留项目 ID、已保存草稿、编辑历史、已有账号与分配并使旧登录失效；任一文件不一致就不创建目标状态目录。若旧平台没有账号库，迁移输出会明确提示，随后使用上文交互命令创建首位管理员。迁移不复制可再生成的本机播放缓存，Ubuntu 首次打开项目时需要重新准备或复用 NAS 缓存。迁移完成并创建管理员后再运行上面的 `up -d`，逐项目验收。迁移包含账号和个人数据，确认 Ubuntu 验收和备份后按公司规则保管或清理。本机服务在 Windows 和 macOS 均可点选视频文件或原视频目录；Ubuntu 服务仅以完整 NAS 采集目录作为新项目领取单位，支持目录浏览或填写 NAS 完整路径。访问者电脑上的本地文件不会自动出现在 Ubuntu 服务器上，需要通过本机服务同步进度和最终 JSON。

## Windows 本机模式的服务器准备 NAS 素材

NAS 素材可以由 `relty-server` 读取、生成播放缓存并打包，再下载到本机。服务器通过有线网络读取 `/mnt/nas/`；电脑继续使用 Wi-Fi，无需接网线。原视频不上传到服务器，也不下载到本机。标注页面仍读取 `.local/projects/<项目ID>/playback/` 中的普通预览、倍速视频、封面和悬停图，本机草稿及四轴标注流程不变。

服务器使用有线地址 `192.168.2.25`，部署目录为 `/home/relty/services/datamark-worker/`。服务仅监听服务器的 `127.0.0.1:18120`，本机通过专用 SSH 密钥建立 `127.0.0.1:18121` 隧道；浏览器访问的本机应用仍是 `http://127.0.0.1:8765`。无需在局域网开放工作服务的 HTTP 端口。服务器的 `state/` 用于处理中间文件和任务记录；完成的缓存包持久保存到原视频目录的 `.datamark-cache/remote-v1/`，例如 `FPV/.datamark-cache/remote-v1/`，不修改原视频。

首次部署在本项目根目录的交互 PowerShell 中运行：

```powershell
.\deploy\deploy.ps1
```

部署脚本使用项目内 Python 执行 `deploy/deploy_worker.py`，提示准备好后再进行 SSH 登录；密码仅在 SSH 终端中输入。它安装项目专用 SSH 密钥、配置服务器运行环境和服务，并将本机连接配置保存到 `.local/remote/worker.json`。密钥、令牌和已信任主机记录也保存在项目的 `.local/remote/` 内，不提交到 Git。首次部署完成后，平台自动建立隧道、提交准备任务和下载缓存，无需每次输入密码；关闭平台后本机隧道停止，服务器已接受的处理任务可以继续。

`worker.json` 包含 `enabled`、`host`、`user`、`port`、`local_port`、`identity_file`、`known_hosts_file`、`host_key_alias`、`token_file` 和 `mappings`。文件路径为本机绝对路径；令牌从 `token_file` 指向的文件读取，不写入源码。当前服务器有线地址使用已验证的同一主机记录，`host_key_alias` 为 `192.168.2.126`。默认共享目录映射如下，实际导入路径应匹配配置中的 `local` 前缀：

| 本机共享目录 | 服务器目录 |
|---|---|
| `\\Relty\datasets` | `/mnt/nas/datasets` |
| `\\Relty\collector-data` | `/mnt/nas/collector-data` |
| `\\Relty\homes` | `/mnt/nas/homes` |
| `\\Relty\docker` | `/mnt/nas/docker` |

准备遵循三级顺序：先复用完整有效的本机缓存；本机缺失时由服务器检查原视频旁的 NAS 缓存包；NAS 也无有效缓存才生成与原流程兼容的精简视频、快进视频、缩略图和悬停图集。缓存身份包含原片指纹、时长和预览规格，包与元数据分别保存为内容 ID 对应的 ZIP 和 JSON。写入使用独立临时文件、校验和及原子替换；NAS 保存和校验成功后才提供下载，并清理该任务的服务器中间视频、散文件和本地 ZIP。NAS 写入失败时保留服务器已完成的包，重试优先补保存，不重新转码。旧版服务器已有的有效 ZIP 会在对应素材再次请求时迁移到 NAS。

本机从服务器下载 NAS 中的缓存包，校验后安装到原播放缓存目录，成功后删除本机下载临时包；播放时仍只读取本机文件。页面区分“检查 NAS 缓存”“服务器处理中”和“下载到本机”，命中 NAS 时无需重新生成。未映射的本机视频继续使用本机准备流程。选择和列出共享目录时仍可能通过 SMB 读取少量目录元数据。已完整保存在本机的旧缓存不会仅为补存 NAS 而重新上传或转码。

服务器双任务配置为 `DATAMARK_WORKER_SLOTS=2`、`DATAMARK_FFMPEG_ENCODER_THREADS=2`，两个任务各有独立准备上下文，同一素材请求去重；容器仍限制为 4 CPU、6 GiB 内存。若实测双任务收益不足，可回退为单任务、4 编码线程，不改变缓存格式。没有开启核显加速或新增系统驱动。任务日志记录排队、NAS 检查、各转码阶段、打包、NAS 保存和清理耗时；本机记录等待、下载校验及安装耗时。缓存包直接存储已压缩的视频和图片，避免重复压缩。下载进度约每 250 毫秒更新，取消和断点续传仍按收到的数据块及时处理。

远程请求或缓存包下载遇到可恢复的连接故障时，平台会自动重连，等待间隔依次为 1、2、4、8、15、30 秒，之后保持 30 秒；每次重连最多自动尝试 5 分钟。准备页面显示“重新连接服务器”和下次重试的等待时间，保留当前进度及已完成的缓存；连接恢复后继续准备，缓存包通过 HTTP Range 从已有下载位置续传。超过重试时限仍未恢复时，页面显示错误并提供手动重试。认证、权限、素材冲突、数据校验或磁盘空间不足等错误直接提示，不进入自动重连。NAS 素材不会因重连失败而改为本机转码。

单个片段的素材或校验失败会保留该项错误，其余片段继续准备，页面持续更新已就绪和失败数量。整批结束后可以重试失败项，也可以选择“跳过失败片段并标注”，查看文件清单并勾选确认后进入标注。至少须有一段可用视频，且其余任务全部结束；未准备完成的片段不能直接进入播放。跳过只改变本项目的标注范围，不删除原片、NAS 缓存或本机已完成缓存，不移动任何视频的时间坐标；时间轴对应区间留空，导出的 timebase.skipped_videos 记录文件名、区间和失败原因，覆盖校验仅针对未跳过的录制范围。选择会保存在本机项目中，并可从准备页“恢复已跳过片段”。已有标注与新增空档冲突时禁止跳过，保留草稿。用户主动取消、切换项目或关闭平台时仍会停止当前本机准备任务。

下载完成的项目可以在断开 NAS 和服务器后继续播放、标注和保存本机草稿；新的 NAS 素材准备、缺失缓存修复及 NAS 写回需要服务器可用。点击“写回原目录”时，映射目录的四个固定 JSON 及自定义轴文件经服务器写入采集根目录的 `timeline/`，继续检查外部修改冲突并保留 `.annotation-backups` 备份；只有写回成功才显示完成。正式导出到本机不要求连接服务器。

此流程减少本机重计算和无线传输的原始数据量；实际准备时间取决于服务器负载、NAS 读取速度、素材时长和缓存包大小，不预设加速倍数。服务器生成的预览规格和本机播放路径不变，播放阶段不增加服务器往返请求。

## 操作流程

1. 点击“新建项目”，可先填写项目名称。Windows 或 macOS 本机服务可通过系统选择窗口多选视频或选择原视频目录，也可填写本机可访问的完整路径。Ubuntu 服务可在网页中逐级浏览 NAS，选择完整采集目录，或填写服务器可访问的完整 NAS 目录路径。新 NAS 项目按目录领取，避免同一文件进入两人的草稿；本机选择目录也可写回该目录的 `timeline/`。单独选择视频可预览和导出 JSON，但不关联统一原采集目录，不能直接写回 NAS。所有 NAS 方式均由 Ubuntu 直接读取原视频，不复制到平台。
2. 从文件名读取视频拍摄开始时间，支持 `设备编号_YYYYMMDDHHMMSS_片段序号.扩展名`，例如 `A09999_20260911131330_0000.avi` 表示 2026-09-11 13:13:30，`A09999_20260911131332_0001.avi` 表示同日 13:13:32。中间 14 位决定现实起点，末尾 `0000` / `0001` 是序号，不作为毫秒；第二段位于全局时间轴第 2 秒，是否有空档由第一段实际时长决定。保留视频原有的 `.avi` / `.mp4` 等扩展名（不区分大小写）。按真实拍摄时间排序，以最早视频开头作为时间轴零点，保留中间没有录制的空档；播放会跳过空档继续下一段。每段保留独立原始文件，不生成合并视频。视频始终保留原位置，平台只记录引用路径。
3. 左上预览视频，点击倍速分段按钮，即时切换 `0.5、1、2、5、10、50、100` 倍速，高亮滑块指示当前档位。在下方视频轴或标注轴空白处定位，也可按住蓝色光标或轴面拖动；所有手动调整视频进度的操作都会先暂停，拖动松开后也保持暂停；需要继续时按空格或点击播放。鼠标悬停在视频轴、刻度尺或任意标注轴时，显示贯穿各轴的竖线及预先生成的图片、时间轴时间与现实时间；靠近视频分界、标注起止点或锚点时自动吸附，点击后播放头定位到该时间。悬停本身不改变播放位置；图片每秒采样并注明预览帧时间，真实断档注明无视频。点击轴名或右侧类型选项切换标注面板；点击已有色块则选择该标注并定位。50 / 100 倍采用预生成的 640×360 快进视频连续播放，避免反复跳转解码；暂停或切回低倍速时恢复本机普通预览，并定位到相同的时间轴时点。快进预览无音频，抽帧仅用于快速浏览，JSON 仍使用原时间轴；录制间隔自动跳过。
4. **场景：**初始提供“室内”“室外”。**姿势：**初始提供“动”“坐”“站”“躺”。每条轴的标签按钮可在当前项目的“管理标签”中增减。尚无状态标注时，先选择初始标签铺满全部已录制的连续范围（`recording_runs`），真实断档保持空白；之后在变化时间点击标签切换状态，同一轴不重叠，切换保留后续已设定的状态边界。已有“车内”“其他”等旧标注原样保留，不自动迁移、不提示重分类；这些标签不再作为默认新标注选项。
5. **大类：**初始提供“专注、活动、用餐、通勤、社交、放松、休息、其他”，同样可增减标签按钮。“单点切换”与姿势相同，先选择初始标签覆盖录制时间，再在变化处切换；“时间段叠加”则填写起止时间、选择标签并保存，允许与已有大类重叠。例如“专注 0–10 分钟”上可叠加“用餐 3–5 分钟”。后续单点切换不改动另行添加的叠加区间。大类可以不标注或只标注部分时间，不要求全覆盖，也不会阻止导出和写回。
6. **习惯：**可以先填写内容，也可以先标记时间。可添加常用内容的快捷标签按钮；点击按钮只填入内容，仍可自由输入。选择“持续习惯”，依次“标记开始”“标记结束”；或选择“瞬时事件”，点击“标记发生时点”。补齐内容后点击“保存标注”。不同内容允许时间重叠，按开始时间排列；跨越录制空档的区间会自动拆成有视频的片段，空档内不能添加时点。
7. **锚点选区：**将播放头定位后点击“添加锚点”或按 `Ctrl + 空格`，在该时间显示锚点；当前位置已有锚点时，同一操作会删除该锚点，后续锚点编号自动前移。最多保留三个，继续添加会移除最早添加的一个。`1–2 00:00:00`、`2–3 00:00:00` 两个区间按钮直接显示各组锚点的间隔，点击按钮即按该组锚点的时间先后选中区间；尚未形成的区间显示 `--:--:--` 并禁用。工具栏另行显示当前播放头到最近一个锚点的间隔。所有时长均采用时:分:秒格式。选中区间后使用现有标注面板选择标签或填写习惯内容。场景、姿势覆盖选区内原标注并保留区间外内容；大类、习惯在选区内叠加。区间跨越真实断档时，仅保存有视频的部分。完成一次区间标注后自动取消选区，并清空本次标注输入；锚点及间隔显示保留，可再次点击区间按钮重新选择。场景、姿势点击标签即完成；大类、习惯点击保存后完成。输入校验未通过时保留选区；点击刻度尺、视频轴或标注轴会退出选区，原有定位和色块选择操作继续生效，锚点及间隔显示保留；锚点区的清空按钮一次删除全部锚点和选区。锚点和选区仅为当前操作辅助，不写入标注 JSON。
8. 点击任意标注色块或右侧记录，修改内容和时间，或按 `Delete` 删除已有整条标注。场景、姿势、大类删除后，新增空白由同一连续录制范围内的前一段顺延；删除首段或唯一一段时直接留空，大类仍被其他标注覆盖的部分无需补齐。习惯删除后不补齐。输入框中 `Delete` 仍正常删除文字。正在编辑但尚未保存时，先保存或取消，再切换项目、类型或其他记录，避免丢失输入。时间可输入秒数，或 `HH:MM:SS.mmm`。底部“撤销”可撤销修改或删除，“恢复”可恢复撤销；撤销后有新修改会清空恢复记录。
9. 改动自动保存到本机草稿，草稿允许未标注空白。确认状态栏显示“已保存本机”；有保存错误时点击“重试保存”。“最近项目”可继续已保存工作。旧项目新增的大类默认为空，不推断或改写现有标签。
10. 点击 **导出 JSON**，下载包含四个预置轴 JSON 及当前项目自定义轴文件的 ZIP；目录导入还可点击 **写回原目录**，将这些文件保存到采集根目录的 `timeline/` 文件夹。读取时优先使用该文件夹中的标注，兼容旧版直接放在根目录的标注；新写回不会删除根目录旧文件。导出前，当前启用的场景和姿势轴必须覆盖全部有视频的时间；写回时允许启用的场景轴全部或部分留空，启用的姿势轴仍须覆盖全部有视频的时间。真实断档无需填充，大类及自定义轴允许全部或部分留空；删除预置轴会清空其标注，但四个 JSON 仍全部写出。导出和写回前都须结束所有事件区间。

“管理标签”只影响当前项目；删除标签时，该标签对应的已有标注一并删除，确认框显示条数。删除姿势或场景标签可能留下未标注区间，须按上述覆盖规则补齐后才能导出或写回。姿势 `Z/X/C/V` 快捷键只对应仍存在的“动/坐/站/躺”，新标签使用按钮。自定义状态轴也可增减按钮；习惯与自定义事件轴的按钮只是可选的快捷填写内容。

漏掉视频时，先打开对应项目，再点击右上方 **补导入视频**。可选择一个或多个文件，或填写单个文件／采集目录路径；视频加入当前项目，同名视频跳过，不覆盖。项目名称保持不变，旧预览缓存继续复用。补导入前先保存本页草稿；新增视频重新按文件名排列，已有标注按原视频内的位置调整，较早视频加入后现实时间仍可追溯。新增视频默认留白，跨过新增片段的旧标注会拆分；若追加到末尾，尚未结束的事件区间会在原视频末尾结束并提示。补导入完成后，自动检查并补齐缺少的预览，完成后再进入标注；导出的全部时间轴文件包含新增素材。补导入后撤销历史重置，并清除临时锚点和选区，避免旧坐标覆盖新时间轴。新增素材中，启用的场景、姿势轴标注补齐后才能导出；写回只要求启用的姿势轴补齐，大类及自定义轴允许留空。

时间轴默认每屏显示约 1 小时，短项目显示全程。鼠标放在时间轴内，按住 `Ctrl` 向上滚轮放大、向下缩小，以鼠标所在时间为中心；最细每屏 5 分钟，最宽显示整个项目，可点击“1小时”恢复默认。缩放不改变播放位置、锚点或选区；工作台内的 `Ctrl + 滚轮` 不再缩放浏览器页面。鼠标位于标注轴条带时，普通滚轮向上／下分别向前／后浏览时间；其它区域仍可使用 `Alt + 滚轮`、触控板横向手势及底部横向滚动条左右浏览。顶部左右按钮每次移动半屏，“回到光标”定位当前播放位置。

当前项目启用的场景、姿势、大类、习惯预置轴与自定义轴同时显示，时间刻度与视频轴固定上方。大类、习惯及自定义事件轴各自最多显示两层重叠标注；鼠标位于重叠轴内时用 `Alt + 滚轮` 上下查看其余层，选中深层标注时也会自动露出。未选择项目时，预览区引导新建项目并选择素材，四条预置轴作为示例可见；素材就绪后才显示右侧标注面板。项目切换、新建、补导入、素材准备和标注输出集中在右侧上方，导出与写回归在“标注输出”下。标注记录通过时间轴色块查看和编辑，编辑历史入口在标注面板标题旁。保存状态保留在顶部，异常时提供重试与恢复副本入口。

导入、补导入和手动切换项目时，会进入素材准备页面。刷新页面恢复最近项目时先读取已有准备状态；素材已就绪则载入预览图片并直接进入标注工作台，不重复发起准备，也不要求再次点击“开始标注”；缓存缺失或失效时才继续准备并显示进度。清理本机预览后不自动恢复该项目，重新打开页面停留在素材选择界面；手动打开旧项目时才重新准备。准备仅处理缺失或失效的素材。配置了服务器映射的 NAS 素材由服务器准备并下载，本机素材继续直接生成精简视频、倍速视频、封面与悬停图。关闭准备页面会返回项目选择界面，不会进入尚未准备好的标注页。首次准备耗时较长，之后复用已完成缓存；补导入复用旧片段，只准备新增素材。

原视频始终在原目录。旧版在原目录 `.datamark-cache/<项目ID>/preview/` 生成的完整预览继续保留，本机准备流程可复用；新的标注准备直接生成精简预览，不再先生成这份大型中间视频。在 `.local/projects/<项目ID>/playback/` 保留一份极精简播放缓存：普通预览为 480×270、保留原帧时序，视频目标码率约 256 kbps、音频约 32 kbps；另保存倍速预览和缩略图，已有有效素材直接复用。配置映射的 NAS 素材由服务器生成这套相同规格的文件再下载到本机。此画面适合快速浏览和标注，清晰度低于原片；原视频、标注坐标和 JSON 时间均不改动。关闭平台后本机缓存保留，下次无需重复下载或转码；“清理本机预览”只释放该本机缓存，保留项目和 NAS 副本。

标注页面的播放、倍速、时间轴封面和悬停图片均使用本机精简缓存，不在每次点击时读取共享目录。原目录和本机的缓存文件夹均有 README.md 说明；缓存不是原视频备份。本机素材尚无可用视频缓存时需连接原磁盘完成首次准备；已有有效精简视频时可在本机补齐快进和图片。NAS 素材需要补齐时经 Ubuntu 处理，公网浏览器在进入工作台前完整下载普通与倍速视频到电脑；重新打开仍须连接 Ubuntu 登录和校验项目状态，已有完整浏览器缓存无需重新下载视频。

悬停画面使用160×90、每秒一帧的JPEG图集，不再创建第二个视频解码器。连续移动鼠标不等待停稳；同一图集内直接切格，切换图集时保留标明时间的上次画面，初次读取先显示标明为封面的图片。主预览仍按毫秒光标定位。准备页面会在进入标注前补齐缺少的悬停图片；优先复用已有图片，缺少时按素材来源在本机或服务器生成。

工作台固定在一屏内：视频随窗口缩放，右侧标注面板独立滚动；当前启用的场景、姿势、大类、习惯预置轴显示在自定义轴之前。轴数较多时，鼠标位于轴名区域可纵向滚动标注轴列表，时间刻度与视频轴保留在上方；大类和各事件轴最多显示两层高度，更多重叠层可用 `Alt + 滚轮` 在对应轴内部上下查看。

标注面板的“添加”可重新添加已删除的场景、姿势、大类、习惯预置轴，也可为当前项目创建自定义时间轴。状态轴需要预先填写标签，同一时刻只有一个状态；事件轴可自由输入内容，支持瞬时事件、持续区间和重叠。最多添加 16 条自定义轴，自定义轴允许留空，不要求覆盖整段录制。选中任一轴后，面板标题旁的删除按钮可删除该轴及其标注；重新添加预置轴时从空白开始，导出与写回仍保留该轴的空 JSON，覆盖检查仅针对当前启用的场景和姿势轴。自定义轴如已写回 NAS，其文件会在下次写回时核对、备份并删除。轴的增删只影响当前项目；当前不提供修改轴定义的操作。

右上角齿轮按钮打开“进度快捷键设置”，可分别调整普通左右键、Shift + 左右键、Ctrl + 左右键、Ctrl + Alt + 滚轮和 Shift + 滚轮的移动步长（0.001–3600 秒，最多三位小数）。点击“保存设置”立即生效，并在当前浏览器记住，适用于所有项目；“恢复默认”后仍需保存，“取消”或 Esc 放弃本次修改。设置窗口内左右键和空格用于正常编辑，不触发视频控制；调整进度自动暂停的规则保留。

姿势快捷键为 `Z` 动、`X` 坐、`C` 站、`V` 躺，无需先切换到姿势面板；从当前播放位置向后修改到下一已有姿势分界，没有后续分界则到当前连续录制结束。首次选择覆盖全部已录制范围，真实断档留空，正式输出仍要求姿势全覆盖。快捷键始终使用播放位置，不使用锚点选区；鼠标标签按钮仍支持选区标注。输入框、中文输入法组合输入、弹窗、素材准备、拖动时间轴、按键长按期间不触发；有未保存编辑时保留输入并提示处理。`Ctrl + Z/X/C/V` 继续执行原有撤销或剪贴板操作。

Shift + 滚轮默认每次移动 1 秒，原来保存的其他四组步长不受影响；鼠标位于时间轴条带时，普通滚轮即可横向浏览。

默认快捷键：`空格` 播放／暂停，`← / →` 前后 0.1 秒，`Shift + ← / →` 前后 1 秒，`Ctrl + ← / →` 前后 30 秒，`Ctrl + Alt + 滚轮` 每次前后 5 秒（向上后退、向下前进；整个工作台可用，不触发时间轴缩放），`Shift + 滚轮` 每次前后 1 秒（向上后退、向下前进），`Ctrl + Z` 撤销，`Ctrl + Shift + Z` 恢复撤销，`Delete` 删除选中的已有标注色块（输入框中正常删字）。左右键和空格在标注工作区固定控制视频，即使按钮、输入框或时间轴已聚焦，也不会触发其他操作；中文输入法选字期间、导入弹窗内除外。顶部“工作台全屏”按钮隐藏浏览器地址栏和标签栏，按 `Esc` 退出；页面同时阻止 `Ctrl + 滚轮` 和 `Ctrl + + / - / 0` 改变浏览器缩放。浏览器及系统保留的关闭、刷新、地址栏等快捷键仍由浏览器管理。

素材准备阶段，全部使用服务器的任务最多同时协调 2 段视频，不受本机逻辑处理器数量限制；需要本机转码时仍要求电脑至少有 4 个逻辑处理器才启用两段并行。同一任务内存在重复素材引用时自动逐段处理，避免同时写入同一缓存。本机素材由本机 FFmpeg 生成缺少的精简预览，配置映射的 NAS 素材交由服务器处理；页面显示各段进度，区分检查、复用、NAS 缓存检查、本机生成、服务器处理和下载。已经完成的素材会复用，异常中断后可重试。进入标注后无需重新转码，并提前载入下一段本机视频。点击或拖动时间轴时只在松开后定位一次，拖动过程中更新光标；高倍速下手动调整进度同样暂停并切回普通预览，保留原时间轴精度；拖动过程中不恢复播放。浏览器取消旧的视频读取请求时，后台会停止对应读取，避免过时的传输占用读取资源。已显示的画面在短暂缓冲时保留，超过短暂延迟才显示小提示。本机精简预览降低分辨率和码率、加密关键帧，同时保留原帧时序。原始视频不改动。首次准备仍需读取和解码原视频，因此长素材仍会花费时间。

## 输出格式

- `scene.timeline.json`：场景轴。
- `posture.timeline.json`：姿势轴。
- `category.timeline.json`：大类轴。
- `habit.timeline.json`：习惯轴。
- `custom_<ID>.timeline.json`：每条项目自定义轴各有一个文件；仅在添加该轴的项目中产生。

当前正式输出为 `schema_version: 3` 的四个预置轴文件加项目自定义轴文件。即使删除某条预置轴，对应文件仍以空 `segments` 输出。平台兼容读取 `schema_version: 1` 的旧三文件和 `schema_version: 2` 的旧四文件；旧标注没有可信的标注人信息，不会自动推断。导出时检查启用的场景、姿势轴覆盖；写回时只检查启用的姿势轴覆盖。写回后重开项目会保留未标注的场景空白及已删除的轴状态。

每个文件包含 `schema_version`、共同的保存批次 `save_id`、采集信息、标签表 `labels` 和记录 `segments`。时间单位为毫秒，起点是最早视频的拍摄开始时间；各视频在轴上的位置由文件名中的拍摄时间决定，空档计入总时间跨度。`timebase.videos` 保留各视频相对路径和轴上起止时间，可回溯原始素材。每个文件的 `timebase.fixed_tracks` 记录当前启用的预置轴，`timebase.track_labels` 记录四条预置轴的项目标签按钮；旧文件缺少字段时使用原默认值。存在自定义轴时，`timebase.custom_tracks` 包含项目轴及其标签清单；对应文件另有 `axis_name` 和 `axis_mode`，重开项目据此恢复自定义轴。

版本 3 的单条 `segments` 记录可包含 `created_by`、`created_by_name`、`created_at`、`updated_by`、`updated_by_name`、`updated_at`。前两个身份字段分别是账号 ID 与保存时的显示姓名；时间字段为 UTC ISO 8601。已有历史不完整的记录可缺少这些可选字段。独立的编辑历史保存在本机草稿数据库，不加入导出的 ZIP。

每条标注还包含现实时间 `start_time`、`end_time`，采用六位字符串 `HHMMSS`，例如 `"150456"` 表示 15:04:56，`"000005"` 表示 00:00:05。这些时间根据最早录制时间加对应毫秒偏移换算，保留录制间隔；同时输出 `start_date`、`end_date`（`YYYY-MM-DD`）区分跨午夜记录。时区为 `Asia/Shanghai`；现实时间显示到秒，原始毫秒字段保留精度。瞬时事件的两组时间相同。原有草稿无需修改，重新导出或写回即可得到新字段。

区间记录使用 `kind: "interval"`，起止语义为 `[start_ms, end_ms)`；事件时点使用 `kind: "point"`，`start_ms` 与 `end_ms` 相同。场景、姿势和自定义状态轴区间互斥，大类、习惯和自定义事件轴区间允许重叠。大类另带 `mode: "state"`（单点切换产生的状态区间）或 `mode: "overlay"`（额外叠加区间），用来保证后续单点切换保留叠加内容。草稿允许未标注空白及尚未结束的事件 `end_ms: null`；导出要求启用的场景、姿势轴完整覆盖录制范围，写回只要求启用的姿势轴完整覆盖；大类和自定义轴可留空，两种输出均不允许未结束的事件区间。

目录模式写回前会检查源素材与已有 JSON 是否发生外部修改；不一致时给出冲突提示。旧版本保存在原目录的 `.annotation-backups` 中。只有显示“已写回”才表示原目录保存完成；“已保存本机”表示 SQLite 草稿已保存。

### 相机分段的秒级时间误差

`A09999_YYYYMMDDHHMMSS_序号.avi` 的文件名只能给出整秒时间，视频时长仍按帧计算。例如 13:11:35 开始的素材长 600.533 秒，而下一段名字为 13:21:35，会出现 533 毫秒的名义重叠。对同一相机、相邻序号、递增的秒精度时间戳，若原始相邻边界重叠和累计校正均不超过 3000 毫秒（含 3000），且原始名义间隔不足 1000 毫秒，平台将下一段接在上一段实际结束处，保留每段全部帧和原文件。单个原始边界重叠或累计校正超过 3000 毫秒、不同相机、序号不连续、时间相同或明确带毫秒的时间戳仍按严格规则检查。两个上限分别用于限制单段误差与连续片段的累计偏移。

相同相机、连续序号的正向亚秒接缝也按秒精度误差判断：实际接缝与原始相邻边界误差均不足 1000 毫秒，且相邻片段校正量均不超过 3000 毫秒时，按连续录制标注。视频条在接缝处连续显示，场景、姿势、大类和持续习惯可跨文件保存为完整区间。旧场景／姿势若恰好在这类接缝结束，并在紧接的文件中以同标签重新开始，打开时会接续为一条；大类和习惯记录保留原有边界。真实断录不合并。导出 timebase 的 recording_runs 和 continuity_bridges 记录连续范围及判断依据，已有视频坐标和标注时间不移动。

这是在允许误差范围内作出的时间对齐估计，并非确认真实拍摄时间完全连续。原始名义间隔达到 1000 毫秒时，不用此前累计偏移强行接续。导出规则使用 v2，明确区分重叠和累计偏移的 3000 毫秒含端点上限与名义间隔的 1000 毫秒不含端点上限；导出保留原文件名时间、名义起点、对齐偏移和使用的规则；导入提示会列出校正次数与最大偏移。没有录制的长间隔继续保留，间隔后的下一段仍以文件名时间定位；前段若有偏移，间隔长度会相应变化。原有无偏移项目的时间轴不变。

可通过“新建项目／补导入视频”选择本机视频或填写路径（例如 `E:\VIDEO`）；选择文件与选择目录都不会复制原视频。


高倍速预览在素材准备阶段从精简视频生成，最终存放在本机播放文件夹；配置映射的 NAS 素材在服务器生成后随缓存包下载，本机素材仍可复用已有原目录倍速缓存。

## 项目名称、存储与删除

新建项目时可填写名称；选择目录并留空时，直接使用所选文件夹名（选择 `FPV` 子目录时即使用 `FPV`）。单独选择视频文件并留空时，仍按首次导入时间（北京时间）生成，例如 `0914-20-32`。项目选择框右侧的铅笔按钮可重命名当前项目；名称最多 80 个字符，自动去除首尾空白。允许同名项目，由内部独立 ID 区分。重命名保留标注、播放位置、锚点、当前输入和撤销记录，不移动原视频或缓存；之后导出及写回使用新名称，已导出文件不会自动修改。再次读取已导入的原目录会打开原项目并保留原名称；补导入也不改名。旧项目启动时自动迁移，缺少首次导入时间的，依据最早可查的本地导入目录或缓存创建时间补齐，并记录 `import_time_estimated`。

`.local/projects/<项目ID>/` 保存项目准备记录和 `playback/` 精简播放缓存，标注草稿存于 `.local/annotations.sqlite3`；原视频及完整预览缓存留在原素材目录。旧的目录引用项目在原目录可读写时迁移已有缓存；旧上传项目点击“关联原目录”，核对全部同名原视频、大小和完整文件内容一致后，复用并迁移已有缓存，更新路径，最后清理平台中的已核验重复副本。原目录未知、缺失或内容不一致时不删除旧副本，已有标注、视频编号和时间坐标保持不变。

项目选择框右侧的垃圾桶按钮现为“清理本机预览”。确认后，停止该项目的本机素材准备任务，仅清理 `.local/projects/<项目ID>/playback/`。项目记录、SQLite 标注草稿、浏览器输入草稿、旧上传副本、原视频、NAS 缓存包、原目录中的完整预览及 `timeline/` 结果均保留；不会删除整个项目文件夹。即使 NAS 离线也可清理。本机文件仍被占用时明确报错，可关闭播放窗口后重试。清理会暂停各标签页的准备和播放，取消该项目的自动恢复；重新打开页面等待选择素材，不会重新下载刚清理的预览。需要继续旧项目时，从项目列表手动打开；下次主动准备时按本机、NAS、服务器重新生成的顺序恢复。原永久删除接口已停用，旧页面调用会被拒绝。

## 文件夹维护

保留 `backend/`、`frontend/src/`、`frontend/test/` 与后端测试、启动/安装脚本及文档；`frontend/dist/` 是当前网页，`frontend/node_modules/`、`.venv/`、`.tools/ffmpeg/bin/ffmpeg.exe` 和 `ffprobe.exe` 是本机运行或构建所需组件。

`.local/projects/` 和 `.local/annotations.sqlite3` 保存真实项目，不能作为普通缓存清理；释放本机预览空间请使用页面中的“清理本机预览”。停止平台和构建任务后，可清理 `.cache/` 的下载缓存、`.tmp/` 的过期临时文件及旧运行日志，使用时会按需重新生成。系统文件选择或其他处理正在使用的临时文件不能删除。

## 外部时间轴对照查看

在当前项目进入工作台后，点击“时间轴对照”，选择固定轴或项目自定义轴并打开 JSON。支持平台导出的 `*.timeline.json`（`segments`），以及 `label`、`start_ms`、`end_ms` 毫秒记录数组。习惯及自定义事件轴支持 `kind: "point"` 瞬时事件，未结束区间使用 `end_ms: null`。单文件上限 20 MB / 50000 条。

查看窗口只显示视频、播放控制及时间轴；仅显示导入的外部轴和项目中同类型的标注轴，其余轴隐藏；两条轴共用刻度、缩放和播放头，悬停仅吸附可见轴的标注分界。点击色块或拖动播放头会暂停并定位视频。空格、左右键及 Shift/Ctrl 组合、Shift + 滚轮、Ctrl + Alt + 滚轮继续沿用已保存步长；Home/End 到项目首尾，Ctrl + 滚轮缩放，轴条带上普通滚轮横移。窗口内可打开进度设置或更换时间轴，Esc / 关闭查看返回标注工作台。查看时不启用标注快捷键。

文件含 `timebase.recording_start` 时按北京时间（无时区默认为 +08:00）对齐到项目录制起点，否则以项目起点为零。导入预览显示对齐方式，跨出范围的区间仅显示项目范围内部分；完全无交集、非法时间或非毫秒单位会报错。外部标签原样显示，不受标注标签词表限制。外部轴仅保留在当前页面内存，不写入草稿、不参与导出或写回，刷新或切换项目后需重新选择文件。
